# 工作佇列開發候選

這份候選在 Repair 5 的單工作流原生準備路徑上，加入工作快照、持久 Queue、PNG 還原補缺及圖片逐張執行。它是獨立開發候選，沒有取代已發布的 Repair 5。真實 ComfyUI 網頁與 GPU 使用流程仍需人工驗證。

## 操作

在畫面上方開啟「工作佇列」。開啟已綁定的 ComfyUI 原生工作流後，按「加入目前工作」取得並保存排入當時的內容。加入與開始分開，後來編輯畫布或網頁不改已保存工作；每项保持原 batch_size。按「開始／恢復」後依序派送，當前項目正常結束且指定輸出收齊才會前進。

加入新工作時需要網頁。已保存工作從已確認的原生序列化執行，派送不再讀取網頁、舊 profile 值或目前畫布；網頁可以關閉，PCS 程序及 ComfyUI 服務仍须運行。排入時無法確認工作流身分、正在输入文字、含未支援的執行回呼或圖片不能保存時，拒絕準備。

等待項目可以移動、排為下一項或移除；「暫停／停止後續」保留當前已提交項目，不發全域中斷、不清空外部工作。執行中加入的工作排在最後；跑空後停止，再加入不會自動開始。重開 PCS 保留清單，先查原嘗試；恢復派送仍需按開始。已確認失敗可以明確重試，產生新嘗試編號並沿用同一份凍結版本；回應不明時只能對帳，不自動重送。結果暫缺只查結果。

「圖片逐張」可以明確選擇一份工作流、LoadImage 輸入與有限圖片清單。可加入檔案、資料夾或已取得的圖片集合；資料夾按檔名排序，集合保持原輸出順序。預設全部逐張，也可指定一張；上一張／下一張只切預覽。純圖片流程不需要假 CLIP。含文字流程需選擇圖片內的來源文字及目標欄位，或提供整批固定 Prompt；缺少指定 Metadata 就停止整批準備，不沿用上一張。其他模型、尺寸與參數保持本次工作流版本。

直接從目前接線加入時，來源集合沒有單張選擇就按原順序全部加入；已有明確選擇則只加入那張。過期的選擇拒絕準備。這是已產生圖片的有限集合處理，不是完整跨工作流管線。

結果仍可在「最近生成」查看與收藏，也能由 Queue 選定工作後按「查看這項結果」。PNG 保留 ComfyUI prompt/workflow 和原有 `prompt_studio` 封套；來源組合與實際執行值分別記錄。圖片組合還原沿用備份、新圖片工作區和 Canvas undo/redo，缺圖會提示。來源還原不保證另一台電腦已有相同模型、節點及圖片資產。

## 持久化與版本邊界

- 桌面新增 `work_queue` 表，待辦不由 `generation_jobs` 的終態清理上限管理。SQLite 原子領取避免同一資料庫的重複開始。
- 擴充新增 `queue_captures` 與 `queue_attempts`，保存已確認工作、每次嘗試及服務端占用狀態。先記錄再交標準 `/prompt` 路由；提交收據與 PNG 封套在同一交易落盤。未知嘗試占用保持，直到有同一 prompt_id 的證據。
- 來源圖片以 SHA-256 保存於擴充的 `queue_assets`，送入專用 ComfyUI input 子目錄；派送前核對內容。沒有複製模型，也沒有新增自動資產清理。移除清單紀錄不刪原圖、生成歷史或資產副本。
- 文件與 PNG 快照版本未新增第二種格式。Queue 工作自身使用 protocol 1；工作摘要涵蓋來源快照、原生圖、文字來源、輸入資產與輸出節點。
- 新舊程式使用各自資料副本。舊版不能理解 Queue；回復使用保留的舊程式及舊資料，新工作與資產保留在新副本。搬移 Queue 資料時須連同擴充資料中的捕捉紀錄及資產，僅複製桌面資料不等於取得全部 ComfyUI 輸入。

## 驗證與支援範圍

離線測試覆蓋原生準備與凍結、三項 batch 10、關閉模擬網頁、回應遺失與重啟、雙連線領取、占用、資產損毀、整項完成與缺結果、PNG 往返、純圖片與逐張資料對應。離屏測試覆蓋 Queue 操作、預覽與單張選擇分離、還原 undo/redo。可用 `tests/verify_queue_preview.py` 在隔離資料執行相關集合，結果寫入 `qa/queue-snapshots`。

前端 seed adapter 仍限定已核對的 ComfyUI frontend 1.43.18 標準 KSampler 控制；不認識的 widget／node 執行回呼會拒絕快照。第一版結果核對支援 SaveImage／PreviewImage 的 PNG，外部文件型自訂輸入未概括保證。服務端原生 `/prompt` 路由、關頁生成、真 SaveImage PNG 往返仍須配套擴充下的人工實測；離線替身和離屏通過不替代這些證據。

本輪不含完整跨工作流、全站視覺改版、定時、資料夾常駐監看、PCS 退出後的背景服務或公開發布。下一階段的跨流程可沿同一工作／嘗試／結果身分加入依賴，先明確選兩份工作流，再把上游已確認輸出集合依序交下游；不能以「最新圖」代替指定上游结果。
