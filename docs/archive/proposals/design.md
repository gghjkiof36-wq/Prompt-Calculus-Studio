## 1. 已確定的產品邊界

第一版是獨立 Windows 桌面軟體，核心流程是「儲存 → 分類 → 選擇 → 組合 → 預覽 → 複製」，可完全離線使用。使用者仍從剪貼簿把文字貼入 ComfyUI。

- 技術方向：Python + PySide6（Qt Widgets）+ SQLite。
- 模組的名稱、數量、順序、單選／複選均由使用者管理，不能用固定的角色／動作／場景欄位代替。
- 每個 Prompt Item 保存名稱、完整 Prompt、中文別名／關鍵字、所屬模組與備註。
- Prompt 可以是一個 Tag、一串 Tag 或一般文字；內容原樣保存，不受 Danbooru 格式限制。
- 名稱、Prompt、別名與備註都能參與即時搜尋。
- 依模組順序組合、即時預覽，最終文字可手動修改並一鍵複製，也能把臨時內容存回素材庫。
- 支援模組與項目管理、基本 Workspace／Preset、SQLite 保存及 JSON 匯入／匯出。
- 採黑色霧面玻璃方向，優先考慮可讀性、清楚的狀態及低硬體負擔。
- 本地文字資料的儲存、搜尋、組合功能不依賴 AI、API、雲端帳號或內容分類服務。使用者自訂的 NSFW 模組與其他模組具有相同的本地資料操作行為。

本次不加入自然語言 AI、ComfyUI Custom Node、模型載入、圖像預覽、歷史記錄或完整使用次數排行榜。依後續補充，Danbooru 詞庫取得及英文／繪師補全提前規劃，並允許用候選使用記錄改善排序。原需求出現的「多個 Workspace」階段重疊，暫以 MVP 能建立並切換 Anima／Illustrious 這類基本預設為提案，進階管理留待後續。

## 2. 操作與資訊架構

主畫面採三欄，是本次設計提案，不是不可更改的限制。

```text
Prompt Studio                         工作區 [Anima ▾]  管理  備份
───────────────────────────────────────────────────────────────
01 模組              02 提示詞素材庫             03 組合與輸出
LoRA                 [中文、英文、別名搜尋…]      依模組順序列出選擇
Artist               [目前模組／全部模組]         每項可直接移除
角色 ●               名稱／Prompt／別名
動作                 名稱／Prompt／別名           自動組合／手動稿狀態
表情                 名稱／Prompt／別名           [可編輯的最終文字]
鏡頭
場景                 [+ 新增提示詞]              存入素材庫
品質                                             [複製 Prompt]
[+ 模組] [管理]
```

### 左欄：組合的骨架

左欄始終依最終輸出順序排列。點模組只改變素材庫的瀏覽範圍，不會取消其他模組的選擇。當前瀏覽模組用背景與左側色條表示；已有選擇的模組用數量表示。這兩種狀態必須分開，避免以為切換分類就換掉 Prompt。

拖曳模組調整順序，立即同步右欄和自動輸出；管理畫面另外提供上移／下移，供不方便拖曳時使用。Module ID 保持不變，重新命名不會破壞項目與工作區的連結。

「新增模組」僅要求名稱與單選／複選。已有資料的模組不能直接無提示刪除；刪除畫面列出項目數及受影響的工作區，讓使用者選擇移到另一模組或連同項目刪除。這是資料保護流程提案，具體移動規則待確認。

### 中欄：快速找到可用內容

使用緊湊的清單列，避免大量圖片卡片占滿畫面。每列固定呈現名稱、兩行以內的 Prompt 摘要和少量別名；完整 Prompt、全部別名與備註在編輯畫面顯示。長內容截斷只影響摘要，不影響儲存或複製。

列的主要區域負責選取；獨立「編輯」按鈕負責管理。編輯不需要雙擊，也不會因為想編輯而意外取消選擇。選中時同時顯示勾選、邊框與背景，不能只靠顏色。

單選模組點另一項會替換同模組的選擇；再次點已選項可取消，允許該模組留空。複選模組逐項加入／移除。以上細節是本次操作提案。

搜尋框預設只搜目前模組，旁邊可切換全部模組。全域結果顯示所屬模組，點選時仍遵守該模組的單／複選規則。搜尋或切換模組不清掉已選內容。這是對「全域或局部搜尋」的可試用提案，尚未當成已確認決策。

### 右欄：看得懂即將複製什麼

上半部用「模組名稱 → 已選項目」呈現組合來源，下半部是可編輯的最終輸出。移除某項只取消本次選擇，不刪除素材庫資料。

「複製 Prompt」是主畫面唯一高亮的大按鈕。成功時用短暫文字回饋，不跳出阻擋操作的對話框。複製內容必須與最終輸出框完全一致，包含使用者當次手動調整。

最終輸出旁有「存入素材庫」，打開一般新增項目表單並預填目前文字。使用者必須選定名稱與模組才會保存，來源項目不會因此被改寫。若只想保存局部片段，可在表單內刪掉不需要的文字。

## 3. 引導方式

引導融入當前工作，不常駐長篇教學，也不要求先走完整個設定精靈。

| 情況 | 畫面回應 |
|---|---|
| 首次開啟、資料庫為空 | 提供「建立第一個模組」與「載入可刪除的範例」兩個明確入口；不擅自寫入大量素材 |
| 模組尚無項目 | 「這個模組還沒有提示詞」及新增按鈕 |
| 搜尋無結果 | 顯示搜尋範圍，可切全域；提示可新增或在最終輸出手動輸入 |
| 單選模組 | 標示「單選 · 選另一項會替換」 |
| 複選模組 | 標示「複選 · 可自由組合」 |
| 自動組合為空 | 保持輸出框可輸入，複製按鈕在純空白時停用 |
| 已手動修改 | 狀態改為「手動稿」，並提供查看最新組合的入口 |
| 原始選擇變動但手動稿仍在 | 提示「組合已更新；手動稿已保留」，不誤稱兩者同步 |
| SQLite 寫入失敗 | 保留輸入內容，說明未保存並提供重試，不顯示假成功 |
| 匯入檔案有問題 | 指出版本、欄位或引用問題，原資料庫保持完整 |

### 視窗縮放

- 三欄以 Qt 分隔器配置，讓使用者調整素材庫／Builder 寬度，記住欄寬。
- 起始尺寸提案為 1280 × 800 邏輯像素，但以螢幕可用工作區限制，避免視窗超出桌面。
- 約 1180 邏輯像素以上採三欄；更窄時提案改為左側模組加中欄「素材庫／組合輸出」頁籤。保留輸出入口，不把三欄硬縮到不可讀。
- 待驗收最小尺寸提案為 800 × 540 邏輯像素；輸入區可隨視窗調整，原生清單允許捲動。

- 對話中的原型為方便閱讀，窄幅時把區域往下排列；正式桌面縮排提案以頁籤為主，兩者不可視為同一個實作。

## 5. 本輪已確認的三個行為

### D01：Workspace 恢復範圍

**已確認：只恢復該工作區指定的固定模組，其餘保留目前選擇。** 例如切到 Illustrious 時換 LoRA／Artist／Quality，角色、動作和場景留著，便於比較不同模型配置。固定哪些模組由使用者勾選，不依賴模組名稱。

本輪不採用「恢復全部選擇」或「其餘清空」的切換方式。

原型已採用確認的恢復方式。管理工作區時勾選要保存的模組，並保存那些模組當下的選擇；切換後仍可改選，固定代表恢復範圍，不代表鎖定不可編輯。原型另有明確「保存目前選擇」動作，不因任一次點選就覆寫已保存預設。

還需確認：模組順序／單複選是否也隨工作區保存、下次開啟程式恢復哪個狀態、刪改素材後舊預設是否跟著更新、未保存工作是否需要切換提示。建議全域素材庫與模組順序共用，工作區先保存選擇；這些額外細節尚未採納。

### D02：手動稿和自動組合的關係

**已確認：分別持有自動結果和手動稿；手動稿不被選擇變動覆蓋，提示可重新產生。**

```text
AUTO：選擇變更 → 重新組合 → 更新輸出
AUTO：使用者輸入 → DRAFT，輸出採用手動稿
DRAFT：選擇變更 → 更新自動結果；輸出仍採用手動稿
DRAFT：查看新組合 → 顯示差異來源及取代按鈕
DRAFT：明確按「以新組合取代」→ AUTO
```

原型採用保留手動稿的方式，仍可繼續選擇其他項目；沒有自動猜測文字差異或把手動內容合併回 Tag。查看最新組合後，要明確按下取代按鈕才返回自動模式。

### D03：Positive／Negative

**已確認：第一版先做一份輸出，之後再擴充。** 未來正／負向分離時，需補上兩份選擇狀態、兩份手動稿、清楚的複製目標，以及工作區要保存哪個通道。不能只加第二個文字框就視為完整支援。

目前原型依此展示一份 Prompt，Negative 留在後續擴充範圍。

## 7. Prompt Builder 的資料保留規則

資料庫保存完整原文。中文、空白、換行、括號、權重、底線與 `<lora:...>` 都是文字；不驗證是否為「官方 Tag」，也不自動翻譯、改寫、重新加權或去重。

LoRA 字串出現在輸出中，僅代表文字被複製；本工具不因此載入 LoRA 檔案，也不保證接收端會解析該語法。

組合器只負責取得有序的模組與已選項目，依選定的分隔政策串接。不要直接按逗號拆解 Item，否則可能破壞使用者保存的內部結構。例如 `(red dress:1.1)`、多行文字或其他自訂語法都應保持原樣。

分隔符提案的邊界情況必須驗收：空白項目、原文已有首尾逗號、英文／全形逗號、括號內逗號、重複 Tag。建議第一版保留原文並提示可手動修正；不要悄悄清洗。原型僅在組合時略過空白片段並去除每片段外圍空白，不拆解片段、不去重，也不刪掉原文中的逗號。此行為屬 D12 提案。

## 8. 技術結構提案

```text
PySide6 畫面
    ↓ 使用者的選擇／編輯
應用狀態與操作規則
    ├─ 純 Python 組合器：有序選擇 → Prompt 文字
    ├─ Workspace：保存的預設與目前工作分開
    └─ 資料存取：SQLite、JSON、遷移、備份
```

不引入 WebView、瀏覽器前端框架、伺服器或 ORM。介面、組合規則和 SQL 分開放，是為了讓後續改色彩、改搜尋或修資料時能知道應修改哪一個檔案。

### SQLite 邏輯資料模型（草案）

下表展示如何滿足需求，並非已執行的 Schema。已反映 D01、D03，D05 等未決項目仍可能影響最終欄位。

| 表 | 主要欄位 | 說明 |
|---|---|---|
| modules | id、name、position、selection_mode | id 穩定不隨名稱變；position 是輸出順序 |
| prompt_items | id、module_id、name、prompt、notes、created_at、updated_at | 每項一模組是 D05 提案；時間欄位為維護提案，不加排行榜 |
| aliases | id、item_id、text | 同一項目可以有多個別名；原文與搜尋用正規化資料分開 |
| workspaces | id、name | 使用者建立的預設名稱 |
| workspace_modules | workspace_id、module_id | 標記固定模組的恢復範圍，包含「明確選擇為空」的模組 |
| workspace_selections | workspace_id、module_id、item_id、position | 各預設的選擇與模組內順序 |
| settings | key、value_json | 視窗幾何、欄寬等少量設定，不拿來藏核心結構 |
| schema_migrations | version、applied_at | 明確版本遷移，更新前先備份 |

若確認 D17，另外保存 session_state，用於最後工作／手動稿；預設表不承擔自動保存責任。收藏與歷史目前不加表。依後續補充，Dictionary 與候選接受次數的資料設計提前納入，詳見 TAG_AUTOCOMPLETE.md，不擴成完整使用統計系統。

使用外鍵約束、參數化 SQL 和交易。模組排序、匯入還原、影響多個預設的刪改要一次成功或整批回復；單選限制在應用層與匯入驗證一起檢查。常用關聯欄位建立索引；重排過程不依賴模組名稱。

## 9. 搜尋設計與中文邊界

MVP 的中文搜尋是資料庫字串比對。例如項目別名含有「紅色衣服」，搜尋這個詞才可找到 red dress／red shirt。不能宣稱沒填過中文的英文 Prompt 也會自動理解同義詞。

提案以名稱、Prompt、全部別名和備註建立搜尋用字串，英文 casefold，保留原始欄位。採參數化子字串比對，搜尋中的 `%`、`_` 應當作字面字元處理，不意外變成 SQL 萬用字元。多個空白分隔的詞是否採 AND 屬搜尋細節提案，原型先採 AND。

中文輸入法尚在組字時不查詢；完成輸入後約 120 ms 合併搜尋事件，快速鍵入時只執行最後一個有效查詢。120 ms 是起始調校值，不是查詢效能保證。

一般 B-tree 索引不能保證加速任意 `%文字%` 子字串查詢，不能以「加索引」代替量測。先用真實資料量檢查；若出現延遲，再考慮背景查詢、分批取回或合適的全文／子字串索引。不要一開始載入中文 NLP 模型。

第二階段 Dictionary 才會處理「中文詞 → 自訂 Prompt 片段」；中文切詞、重疊詞、修飾關係與無法匹配的文字需要獨立設計。一般中英詞典不能直接保證把「紅色洋裝的女孩站著看鏡頭」正確理解成使用者想要的組合。

## 10. 性能與封裝

PySide6 是可行方向，但實際 RAM、CPU、啟動時間與封裝體積必須在成品量測，本次不提供虛構數字。

- 素材庫用 `QListView`、資料模型及 delegate 繪製可見內容，不為每個 Item 建立一整組常駐 QWidget。Qt 的 Model/View 設計把資料提供與顯示區分開，並建議配合樣式表時使用 `QStyledItemDelegate`。[Qt Model/View 文件](https://doc.qt.io/qtforpython-6/overviews/qtwidgets-model-view-programming.html)
- 等高摘要列可考慮 `uniformItemSizes`，長列表需要時分批 layout；完整文字留給編輯器。[QListView 文件](https://doc.qt.io/qtforpython-6/PySide6/QtWidgets/QListView.html)
- 原生 `QPlainTextEdit` 顯示／編輯 Prompt，Qt 剪貼簿 API 執行複製。主程式不包含網頁渲染引擎、不掃描模型檔案、不常駐推論程序。
- 只在輸入、選擇、排序或資料變更時更新受影響的區域；不定時重讀整個資料庫，不每幀重畫整個視窗。
- 不用即時 Blur 或逐卡陰影，避免視覺成本隨項目數增加。
- 大量匯入或備份移到工作執行緒並回報進度；SQLite connection 遵守所屬執行緒的使用方式，避免直接跨執行緒共用。
- 程式自行不需要 GPU 計算；Windows 視窗合成仍可能使用 GPU，不宣稱工作管理員必然顯示零 GPU。

封裝候選先評估 Qt 官方的 `pyside6-deploy`，PyInstaller 是替代選項。Qt 官方提供 Windows 桌面封裝流程；具體工具與版本在最小可用程式建立後實測再鎖定。[Qt 部署文件](https://doc.qt.io/qtforpython-6/deployment/index.html)

開發環境的安裝／封裝可能需要下載套件；完成打包後，日常執行不應需要 Python、終端機或網路。交付目標是可雙擊的 Windows 應用程式，以及可理解的原始碼與修改說明。

## 11. 本地保存與 JSON 備份

資料路徑提案使用 `%LOCALAPPDATA%\PromptStudio\`；程式安裝位置和使用者資料分開，更新執行檔不覆蓋素材。若需要可攜版，另確認是否允許資料跟著程式目錄走。

JSON 使用 UTF-8、可讀的中文與明確格式版本，保存穩定 ID、模組順序、選擇模式、全部項目／別名／備註和工作區引用。搜尋快取不需要匯出，可以重建。資料格式版本與軟體版本分開。

建議的「還原備份」流程：

1. 讀檔，檢查格式版本、欄位型別、ID 唯一性、引用關係、順序及單選規則。
2. 顯示即將還原的模組、項目與工作區數量，明確說明取代範圍；尚不寫入。
3. 使用者在程式內確認執行還原後，以 SQLite backup API 備份目前資料。
4. 在交易中完成還原；任何一步失敗都回復，錯誤保留可理解的訊息。
5. 完成後重建搜尋資料並重載畫面。

原始資料庫運作時，備份應使用 SQLite 的備份介面，不單純複製可能仍在寫入的檔案。Python `sqlite3.Connection.backup` 支援在資料庫仍被存取時建立備份。[Python sqlite3 文件](https://docs.python.org/3/library/sqlite3.html#sqlite3.Connection.backup)

匯出先寫同目錄的暫存檔，成功後再替換目標檔，避免中途失敗損壞唯一一份備份。新版本無法理解的資料格式應拒絕並說明，不忽略欄位後強行匯入。自動備份的份數／保留策略待確認。

## 12. MVP 驗收與實作順序

| MVP 要求 | 主要位置 | 完成時的驗收方式 |
|---|---|---|
| 1. 自訂 Module | 左欄／管理 | 增刪改名稱；加入第 20 個模組，介面仍從資料產生 |
| 2. Prompt CRUD | 中欄編輯器 | 新增、編輯、刪除後重開仍一致；編輯不意外選取 |
| 3. 中文與 Alias | 編輯器／搜尋 | 用不同中文別名都能找到同一項 |
| 4. 原文保存 | Prompt 欄位 | 中文、換行、括號、權重及自訂字串往返不變 |
| 5. 即時搜尋 | 中欄頂端 | 不按 Enter 也更新；中文輸入法不被干擾 |
| 6. 單／複選 | 模組屬性 | 單選最多一項；複選可取消；跨模組互不清空 |
| 7. 模組排序 | 左欄 | 拖曳及上／下移一致，重開仍保留順序 |
| 8. Builder | 右欄 | 僅組合選中的項目，順序符合所選政策 |
| 9. 即時預覽 | 右欄輸出 | 自動模式下資料改變會反映；刪空不留下幽靈項目 |
| 10. 手動修改 | 右欄輸出 | 按確認的 D02 行為處理，手動文字不意外遺失 |
| 11. 一鍵 Copy | 主按鈕 | 貼到記事本與 ComfyUI，文字與輸出框逐字一致 |
| 12. SQLite | 資料層 | 重啟可讀、保存錯誤不假成功、交易可回復 |
| 13. JSON | 備份入口 | 匯出→還原往返一致；壞檔／新版本不破壞現有資料 |
| 14. Dark Glass UI | 全畫面 | 縮放、選中、焦點、長文字可讀，待機沒有動畫循環 |
| 15. Workspace | 頂欄／管理 | 按確認的恢復範圍切換；指定空模組可正確恢復為空 |

實作順序提案：

1. D01–D03 已確認；開始資料表實作前，繼續確認 D04–D07。其他提案可在相對應功能開始前確認。
2. 先建資料層與純 Python 組合器，測試文字保留、選取規則、排序、交易與 JSON 往返。
3. 做原生三欄畫面，接上搜尋、編輯、選取、Builder、手動稿及剪貼簿。
4. 補工作區、匯入預覽、備份與空狀態引導。
5. 用 100、1,000、10,000 項、長 Prompt 和多個 Workspace 做性能測量；記錄硬體、啟動時間、記憶體、搜尋延遲及待機 CPU，超出可接受範圍才優化。
6. 在 Windows 實際封裝，驗證沒有開發環境也能啟動、離線使用、保存及備份；提供雙擊入口、修改說明與錯誤紀錄位置。

本輪沒有執行上述桌面驗收，也沒有安裝依賴；不把原型的流暢程度當成 PySide6 成品的效能結果。
