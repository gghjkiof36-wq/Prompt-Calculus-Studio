# Prompt Studio 0.8.1：CivitAI 搜尋、下載與模型資產

日期：2026-09-13  
文件性質：需求與 UI 交接規格；本次只整理文件，不代表功能已實作或驗收。  
開發目標：使用者在設定頁找到模型，確認版本、檔案及安裝位置，下載完成後立即在 ComfyUI 模型資產頁找到它。

- 下載確認、依 Type 建議安裝位置、檔案檢查、資產登記、下載紀錄與失敗恢復。

- 舊資料相容、個人修改保留，以及既有 CivitAI 草稿問題的整合驗證。

本輪不包含 Trigger 自動啟停、Recipe、生成 History 重構、WebUI 支援，也不擴大為完整 0.9.0 的模型自動辨識或資產管理計畫。Trigger 只顯示、保存，並沿用現有複製／加入組合操作；不另建 LoRA 專用組合系統。下載紀錄只記錄下載與安裝結果，不是生成 History。

## 2. 設定頁結構

左側導覽新增獨立 **CivitAI**，與 ComfyUI 並列：

```text
使用介面
介面個人化
候選與翻譯
個人字典
CivitAI
ComfyUI
```

CivitAI 負責來源搜尋與下載紀錄；ComfyUI 負責本機模型安裝位置、資產管理及使用。資料可預留其他安裝目的地，0.8.1 的下載目的地只有 ComfyUI，不提供未實作的 WebUI 選項。

CivitAI 上方頁籤依序為 **搜尋模型｜下載紀錄｜連線設定**，預設進入搜尋模型。使用現有深色分層、選取與懸停樣式，不增加持續動畫、即時背景模糊或大型圖片牆。

### 搜尋模型

```text
搜尋模型          下載紀錄          連線設定

[搜尋名稱、作者……                         ] [Type] [Base Model] [排序]

搜尋結果與縮略圖                       選取模型
┌─────────────────────────┐          ┌─────────────────────────┐
│ 縮圖  名稱／作者         │          │ 預覽圖、名稱             │
│       Type／Base Model   │          │ [版本選擇              ] │
│       評價摘要／安裝狀態 │          │ Details                  │
│                         │          │ 開啟 CivitAI 頁面        │
│ ……                      │          │ [下載]／[查看資產]       │
│ [載入更多]              │          │                         │
└─────────────────────────┘          └─────────────────────────┘
```

- 左側使用帶縮略圖的清單，延續既有模型資產頁。顯示名稱、作者、來源 Type、Base Model、可取得的評價摘要與安裝狀態。
- 本文件建議先採「載入更多」；如沿用既有分頁元件，仍須限制每批數量，不一次載入全部結果。
- 只請求目前可見的縮略圖；選取後才請求較大預覽。圖片快取須有上限。
- 切換搜尋、篩選或版本時，舊回應不得覆蓋新選取。忙碌、無結果與讀取失敗應有明確狀態及重新嘗試入口。
- 右側版本切換後，預覽、Details、來源連結與下載所指版本同步更新；不可沿用上一版本的數值。
- 「未安裝／已安裝此版本」依來源版本及本機登記、檔案存在狀態判斷，不能只比模型名稱。裝有其他版本時不得標成已安裝目前版本。
- 同一版本有多個檔案時，下載確認仍須列出實際檔案；不能將已安裝一個檔案解讀為全部檔案均已安裝。
- 未選取模型時，右側保留簡短提示；不以空白預覽或大量無內容欄位撐滿畫面。

窄視窗時，先將篩選列移到搜尋框下一行；保留搜尋與右側內容可讀寬度。左右分欄延續既有調整方式，長資訊可換行或捲動，不靠縮小字體容納。

### Details

以下是資訊顯示契約，**不是已確認的 API 欄位清單**。開發組須逐欄記錄實際來源、適用層級與缺值處理，不能為湊齊 UI 推算資料。

| 顯示欄位 | 顯示內容與限制 |
| --- | --- |
| Type | 來源的模型類型，例如 LoRA、Checkpoint；保留來源值。 |
| Stats | 可取得的下載量、使用量等；各數值明確標示意義與所屬模型／版本範圍，不能混用。 |
| Reviews | 來源提供的評價摘要及數量；不得用下載量推算好評。 |
| Published | 目前選取版本的發布日期；不能用模型建立日期代替。 |
| Base Model | 目前選取版本的基礎模型；來源缺值時不得自行辨認填入。 |
| Usage Tips | 來源明確提供的建議，例如 strength；缺少 strength 不視為 1。 |
| Hash | 顯示 Hash 種類、值及對應檔案，可複製；多檔案時不可混成版本共用值。 |
| Trigger Words | 目前版本提供的觸發詞，可多個、可複製；與使用者修改的 Trigger 分開保存。 |
| AIR | 可複製的來源識別資訊；取得或產生依據必須經開發組核實，不猜測。 |

來源沒有提供的值顯示 **未提供**；尚在載入或讀取失敗不能假裝是缺值，也不能顯示上一個模型的資料。長篇描述不嵌入頁面，保留明顯的 **開啟 CivitAI 頁面**，連到目前選取版本。

### 連線設定

集中放置既有的聯網、Token 與連線檢查控制項，不在搜尋頁重複放一組。搜尋、辨識、縮略圖、預覽及下載使用同一聯網設定；關閉聯網後不發起新網路工作，既有工作依取消流程結束。本機資產仍可查看及編輯。

## 3. 下載確認與安裝

點擊下載後使用既有樣式的確認視窗：

```text
下載模型

版本／檔案     已選版本／具體檔案
安裝到         ComfyUI
模型類型       來源 Type
Base Model     所選版本的 Base Model
用途分類       未分類，可由使用者選擇
儲存位置       實際目標資料夾與檔名
檔案大小       來源提供的大小／未提供
校驗資訊       可用的官方 Hash 種類／未提供官方校驗值

取消                                  下載並加入資產
```

若版本包含多個可下載檔案，視窗提供檔案選擇並同步更新大小、Hash、檔名及位置。下載開始前固定所選模型、版本、檔案、目的地與用途分類；背景工作不再從正在變動的 UI 讀取。

### 分類與目錄規則

| 資料 | 用途 | 不應承擔的作用 |
| --- | --- | --- |
| 來源 Type | 與既有本地類型建立對應，建議適合的安裝目錄。 | 不取代舊有本地 LoRA／Diffusion／CKPT 值，也不推定用途分類。 |
| Base Model | 保存模型家族，供篩選與管理。 | 0.8.1 不強制依 Base Model 建立子資料夾。 |
| 用途分類 | 使用者的角色、畫風、服裝、背景等個人分類。 | 不由 Type 或 Base Model 自動推測，不決定實際檔案搬移。 |

- 安裝位置從已配置的 ComfyUI 模型位置建議，不能硬寫成所有電腦都相同的路徑。
- 使用者可以調整目標位置。Type 無法明確對應、或沒有可用目錄時，要求選擇位置，不猜測安裝。
- 同名檔案不覆寫；開始前顯示衝突並讓使用者改名或改位置，開始寫入時仍須防止新發生的同名衝突。
- 不因下載而自動更換活動工作流、套用 LoRA 或將 Trigger 加入 Prompt。

### 完成與失敗

成功順序固定為：**檔案檢查 → 資產登記 → ComfyUI 資產清單可見 → 顯示「已加入模型資產」**。只完成檔案傳輸不能顯示整個安裝已完成。

| 狀態 | 使用者看到的結果與恢復方式 |
| --- | --- |
| 下載中 | 顯示進度並可取消；大小未知時不顯示假的百分比。 |
| 檔案檢查中 | 核對可取得的官方 Hash，並記錄實際本機檔案資訊。 |
| 官方 Hash 相符 | 顯示已核對官方 Hash，記錄種類與值。 |
| 未提供官方 Hash | 清楚標示缺少官方校驗值；即使計算了本機 Hash，也不能稱為官方校驗成功。沿用隔離草稿的區分，不把缺值誤報成成功。 |
| 校驗失敗 | 不加入可用資產；移除未通過的下載暫存，保留失敗紀錄與重新下載入口。 |
| 已取消／下載失敗 | 不登記未完成檔案；紀錄原因及可用的重試操作。 |
| 檔案已下載、登記失敗 | 明確顯示「檔案已下載，資產登記失敗」，保留位置與校驗結果，提供 **重新登記**，不重抓整個模型。 |
| 已加入模型資產 | 顯示 **查看資產**；搜尋頁保留原查詢、捲動與選取，不自動跳頁。 |

重新登記前再次確認檔案存在且與下載紀錄相符；重試登記不得產生重複資產。成功後選擇「查看資產」才切到 ComfyUI 模型資產頁並定位該筆。

### 下載紀錄

記錄模型、來源版本、具體檔案、目標位置、時間、進度／結果、校驗狀態與登記結果。操作依結果提供取消、重試、重新登記或查看資產；不混入生成圖片紀錄。

重開程式後，不把未結束的工作標成成功，也不默默重送下載。已完成檔案但尚未登記的狀態必須可恢復。0.8.1 不以本規格承諾跨重啟斷點續傳；如未支援，重試需清楚表示重新下載。

## 4. ComfyUI 模型資產頁

保留目前的左右分欄、預覽與編輯控制項，只補資訊與篩選：

```text
[搜尋名稱、檔名、觸發詞……                                     ]
[所有類型]       [所有 Base Model]       [所有用途分類]

資產清單                              現有預覽與詳細資訊
縮圖／名稱                            Type、Base Model、來源版本
Type／Base Model／用途分類            作者及來源連結
大小／檔案狀態／來源連結狀態          個人名稱、分類、Trigger、網址、Notes
```

- 寬度足夠時，篩選列可沿用既有單行配置；不足時換行，不壓縮搜尋框及右側內容。
- 每筆顯示縮略圖、名稱、Type、Base Model、用途分類、大小、檔案存在狀態，以及 CivitAI 來源連結狀態。
- 既有本地類型與來源 Type 分開保存並建立對應，未知來源不導致舊資產分類消失。
- 右側在原有預覽、名稱、分類、Trigger、網址與 Notes 之間補入 Type、Base Model、來源版本、作者及來源連結，不另做一套編輯頁。
- 缺少本機檔案時，清楚顯示檔案不存在，不能仍宣稱該版本可直接使用；保留個人資料供修復。
- CivitAI 重新整理只更新來源資料，不覆蓋個人名稱、Notes、Trigger、網址、分類或使用者替換的預覽。

### 用途分類管理

沿用現有「管理分類」視窗，加入 **適用模型類型**，讓 LoRA 可以管理自己的用途分類。

- 支援新增、改名、排序與刪除。
- 刪除分類後，該分類資產改為未分類；不刪除模型或來源資料。
- 分類改動不搬動檔案，也不重寫 Base Model。
- 舊分類與原有資產歸屬完整保留，不自動重新分配到新分類。
- 舊分類沒有適用類型時，遷移必須保留其原先可見及可用範圍，不能因新增篩選而隱藏。
- 角色、畫風、服裝、姿勢等是用途分類範例，不強制改名或覆蓋使用者既有分類。

## 5. 資料與背景工作契約

| 資料層 | 保存內容 | 更新規則 |
| --- | --- | --- |
| 網站來源 | 來源服務、模型／版本／檔案識別、來源名稱、作者、Type、Base Model、Trigger、版本連結、Hash、縮略圖來源及取得時間。 | 由經驗證的來源回應更新；缺值不沿用上一個模型的值。 |
| 本機資產 | 安裝目的地、實際路徑、本地類型、檔案大小／存在狀態、本機 Hash、來源關聯、安裝及校驗結果。 | 以本機檔案及登記結果為準；檔案改變時舊辨識結果不得代表新檔案。 |
| 使用者資料 | 個人名稱、Notes、自訂 Trigger／網址／預覽、用途分類及分類順序。 | 只由使用者操作修改；背景來源更新不得整筆覆蓋。 |
| 下載紀錄 | 固定的版本與檔案、目的地、工作狀態、校驗與登記結果、錯誤原因。 | 供重試與重新登記，避免重複資產或誤報完成。 |

具體資料表與欄位名稱由開發組決定，但必須能區分模型、版本、檔案及個人覆寫，不以顯示名稱作唯一識別。資料升版前備份，保留舊資料讀取及恢復方式。

整合草稿時保留以下修正：

1. 查無辨識結果或檔案改變時，使舊來源失效，不再顯示已辨識。
2. 背景只合併來源欄位，保留等待期間使用者的新修改，包括尚在編輯中的內容。
3. 工作開始前固定參數；背景不讀 UI。Token 修改或清除後，舊回呼不能重新保存 Token。
4. 快速切換模型或版本時只顯示最後選取；忙碌、取消、失敗都有終止狀態。
5. 官方 Hash 相符、缺少官方 Hash、校驗失敗三者分開表示。
6. 所有 CivitAI 網路入口遵守同一聯網設定，本機資產與畫布操作不依賴連線成功。

## 6. 開發順序與完成條件

各階段先完成對應驗證，再接下一階段；不能以新增搜尋畫面取代資料與下載修復。

| 階段 | 工作 | 階段完成條件 |
| --- | --- | --- |
| 1 | 逐項審查並整合隔離草稿的資料覆寫、背景工作、預覽與校驗修正。 | 既有缺陷有回歸證據；0.8.0 本機操作保持可用；來源差異可追查。 |
| 2 | 補齊資產 Type、Base Model、來源版本及適用類型的用途分類。 | 舊資料不失聯，個人內容保留；篩選與分類操作不移動／刪除模型檔案。 |
| 3 | CivitAI 獨立設定板塊、搜尋清單、縮略圖與 Details。 | 完成逐欄來源對照；版本切換、缺值及快速選取結果正確。 |
| 4 | 下載確認、位置建議、檔案校驗與資產登記。 | 搜尋到資產可完整走通；同名不覆寫；登記失敗可重試且不重複下載。 |
| 5 | 下載紀錄、失敗恢復、舊資料及既有 UI 相容驗收。 | 完成以下情境並分別記錄模擬、真實服務、Windows 互動及打包結果。 |

## 7. 驗收情境

| --- | --- | --- |

| A03 | 快速選取 A→B→C、切換版本或搜尋條件。 | 最後只顯示當前選取；取消或失敗後不永久停在載入中。 |
| A04 | 來源沒有評價、strength、日期、Hash 或 AIR。 | 缺值顯示未提供；不推算，不借用其他版本資料。讀取錯誤另行顯示。 |

| A07 | 無法映射的 Type、未配置目錄或同名檔案。 | 要求選擇可用位置／解決同名；不猜目錄、不覆寫既有檔案。 |
| A08 | 官方 Hash 相符、缺少、錯誤。 | 三種狀態各自正確；校驗錯誤不成為可用資產；本機自行計算不稱為官方驗證。 |
| A09 | 成功下載並登記。 | 同一筆資產立即可查，來源版本與位置正確；搜尋頁不跳走，查看資產可定位。 |
| A10 | 下載成功但登記失敗，再按重新登記。 | 保留檔案並再次檢查，無須重抓；一次成功只產生一筆對應資產。 |
| A11 | 取消、斷線、重開程式或本機檔案被移除。 | 不誤報成功、不自動重送；提供與實際狀態一致的重試、登記或檔案缺失提示。 |
| A12 | 來源更新期間修改名稱、Notes、Trigger、網址、預覽或分類。 | 使用者修改保留；新來源資訊可另行查看。 |
| A13 | 查無辨識結果、檔案 Hash 改變或舊回呼晚到。 | 舊來源不冒充新檔案；已刪除資產不被回呼重建。 |
| A14 | 工作中清除 Token 或關閉聯網。 | 舊回呼不回存 Token，後續網路入口停止；本機資產及畫布仍可操作。 |
| A15 | 新增、改名、排序、刪除 LoRA 用途分類。 | 適用範圍正確，刪除轉未分類；原檔案不搬動、不刪除，舊分類不被重分配。 |
| A16 | 小視窗、大字級、不同 DPI 及大量資產。 | 篩選可換行、文字可讀、右側可操作，清單與圖片不造成持續重繪或無上限記憶體成長。 |
