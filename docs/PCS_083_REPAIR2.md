# PCS 0.8.3 待核對阻塞修復候選（0928）

> 歷史候選說明。使用者其後更正直接執行及原生按鍵的行為；目前方案見 [直接執行修復](PCS_083_DIRECT.md)，本頁不代表目前版本已通過人工驗證。

這次修正人工驗證中「ComfyUI 沒有活動任務，但 PCS 一直待核對」的阻塞。前次 0927 候選仍未通過人工驗證。

## 原因

舊任務的桌面紀錄為未確認，擴充保留已提交回執，但服務重新開啟後已沒有原任務的即時歷史。原本的「重新核對」只重查歷史；「取消」回報離開佇列後又回到同一查詢，沒有結束追蹤。移除等待需求也不會處理這筆舊任務。

此外，已斷開的預排程仍向原生按鍵宣告接管；換用新資料副本時，舊視窗的宣告也可能留下。

## 本次操作

1. 關閉舊 PCS。換用同包 ComfyUI 擴充，重新啟動 ComfyUI 並重新整理網頁，再開新候選。
2. 若工具列顯示「舊任務待解除」，直接按旁邊的「解除阻塞」。「取消」也能核對並結束已消失任務的追蹤。
3. 成功後會明確顯示已解除。原任務紀錄保留，沒有重新生成；等待項目仍暫停。保留的普通需求可從「等待 N 次」選擇繼續或移除；預排程項目在模塊內處理。
4. 要測新的三次執行，先移除不需要的舊等待需求，按「繼續」，再按執行；第一輪生成期間再按兩次。

若任務仍在 ComfyUI，或同一服務內的原生提交仍未回覆，解除操作會顯示具體原因，不會清空佇列或取消其他來源工作。「任務紀錄 → 重新核對」會顯示查到執行、等待、歷史、無紀錄或提交中；不以沒有歷史冒充生成成功。

預排程斷開或移除後，內容保留並暫停，但不再接管原生按鍵。PCS 已離線的舊接管宣告會在八秒後失效；仍連線且接著工作流的暫停預排程，需明確按「繼續」。此變更不會自動執行保留項目。

## 人工驗證

- 舊資料的「解除阻塞」與「取消」有明確結果；解除後可提交新工作，不再反覆回到待核對。
- 不接預排程連按三次；尚未提交的輪次使用提交當時文字。
- 預排程斷開後，ComfyUI 手動執行正常；重新接回並繼續後才消耗保留項目。
- 真正在生成時解除不會誤停任務；原生其他來源工作、歷史與等待資料保留。

開發驗證使用原桌面與擴充資料的副本、正式提交與回執路徑及 Qt 操作事件；模擬執行器不使用 GPU。未代為替換使用中的程式、修改原資料或重啟服務。真實網頁與 GPU 結果仍由使用者驗證。
