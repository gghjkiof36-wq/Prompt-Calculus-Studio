# PCS 0.8.4：Stage 操作說明

本輪種子與流程恢復修正、人工驗證及限制見 [修復候選說明](PCS_084_RECOVERY.md)。

本候選以 Stage 作為 PCS 生成入口。使用時保持 PCS、ComfyUI 服務及原生網頁開啟，並使用候選附帶的同版擴充。原生 Run 維持獨立；PCS 暫停或提交未確認不會封鎖原生 Run。

本次修正未接入的 Stage 仍會生成、改線後舊流程阻塞新預排程、預覽圖片無法刪除，以及圖片換節點後文字來源未更新。工作流的節點清單改從已開啟的原生草稿讀取；提交前重新取得原生網頁回覆，區分尚未回覆、找不到目標、重複分頁及操作中的情況。真實原生網頁與 GPU 驗收仍需另外確認。

## 從既有畫布開始

1. 保留既有「畫布 → Prompt 控制 → CLIP 輸入」。確認 CLIP 綁定正確工作流及文字欄位。
2. 在 Canvas 的「功能模組」加入「Stage／執行階段」，把 CLIP 右側「輸出」接到 Stage 左側「輸入」。第一條有效綁定會帶入工作流，之後可在 Stage 的「選擇工作流」更改。
3. 正面、負面 CLIP，以及 ComfyUI 圖片輸入，都接到同一 Stage，即代表一次工作流生成。灰字顯示實際執行的工作流。
4. Stage 右側「圖片」可直接接「預覽圖片」查看全部結果。要指定圖片節點，先接「加載圖片」或「圖片來源」，在那裡選擇節點，再接預覽或下一個工作流。
5. 按底部「執行」。只有一個 Stage、沒有預排程時，每次點擊立即提交當下內容，生成中仍能再按。次數為 3 即提交三次。

也可選「依現有綁定補建 Stage」，依各工作流建立階段並接好控制線。請檢查順序後再執行，這個操作本身不會生成。

**修改 PCS 文字不再即時覆蓋 ComfyUI；按「執行」才套用。沒有接入 Stage 時只套用輸入，不生成。**畫布上單獨放著 Stage，或只將它接到圖片讀取器、預覽、預排程，均不會讓它開始生成。Stage 須接入 CLIP／圖片輸入的控制線，或接在有效前置 Stage 的紫色輸出後。

CLIP 只使用左側送入的文字，包含有效的空白稿；沒有綁定的原生欄位保留。未接 Stage 的 CLIP／圖片輸入只修改它所綁定的欄位；若來源是本輪尚未產生的 Stage 結果，等整條流程收尾後才套用，仍不生成。把 A、B 兩個工作流的輸入接到選擇 A 的 Stage，會套用 A、B 的內容，但只生成 A。

底部保持「次數、執行、取消、活動任務數」。Stage 卡只保留選擇工作流；按活動任務數可查看紀錄及處理保留的工作。預排程保留自己的清單管理。

## 圖片與下一個工作流

```text
Prompt 控制 → CLIP 輸入 → Stage A
                           │ 圖片
                           ↓
                 加載圖片（選圖片節點）→ ComfyUI 圖片輸入 → Stage B → 預覽圖片

Stage A ──文字──→ 讀取文字（選文字欄位）→ Prompt 控制／CLIP 輸入
```

- **ComfyUI 圖片輸入**指定接收圖片的工作流及 `LoadImage`，相當於圖片的 CLIP 輸入。它不讀取 ComfyUI 輸出，不要求重新選一次本機圖片。
- **加載圖片（單張）**接受本機圖片或左側圖片輸入，右側提供圖片及其文字。
- **圖片來源**管理單張、多張、資料夾、明確選定的歷史圖片或本輪 Stage 結果。從「選擇圖片／資料夾」可改選「本次 Stage 結果」，省去跨畫布長線；這仍是明確依賴，B 會等 A 完成。
- **預覽圖片**只觀看、切換及放大，沒有右側輸出；選中預覽不改變下游實際供應的圖片。

Stage 收取該次所有圖片節點的結果。「加載圖片」與「圖片來源」選擇全部節點或指定節點，圖片選單可再指定一張。A 供應三張時，B 會依序處理三張，收齊 B 的結果後才進 C。指定節點或圖片不存在時顯示原因，不以舊圖片替代；若後續 Stage 需要該輸入，就停在該項，僅供預覽則不停止生成。

「讀取文字」接在 Stage 的文字輸出後，選擇該次實際提交的文字欄位。它不猜測正負面、不拆 tags，也不觸發生成。

只需要先後順序時，把 A 右側紫色「輸出」接到 B 左側紫色「輸入」。流程以接線判斷，位置不決定順序。本輪只支援明確的線性流程；A→B→A 可以使用兩個不同的 A Stage 實例。多 Stage 沒有預排程時，次數代表完整流程輪數；流程中再按執行不會疊加另一條相同流程。

### 圖片文字

圖片含有效 PCS 紀錄時，還原相關文字模塊；只有原始正面 Prompt 時保留整段，不拆 tags。接入畫布會顯示以檔名命名的來源文字卡，也可直接接 Prompt 控制。缺少文字或來源不明會顯示原因，不沿用前一張。

圖片來源沒有直接接資料預排程時，一輪成功完成後換到下一張及其文字，**不自動生成下一輪**。換圖之前再次點擊，使用當時仍有效的圖片。

## 預排程

### 保存部分資料

把 Prompt 控制接到預排程的「文字」輸入，再從成對的文字輸出接 CLIP；圖片也可接同一預排程的圖片接點。只保存經過這份預排程的內容，其餘輸入在實際提交時讀取。

空閒時按執行立即開始；忙碌時按執行保存下一項。要固定正面、保持負面即時，讓正面經過預排程，負面直接接 CLIP。

若要先累積幾項再執行，先按這份預排程的「暫停」，再按全域執行加入項目，最後按「繼續」。手動暫停會保留到明確繼續；未按暫停的預排程耗盡後，下一次執行會直接開始。「輸入取值」只顯示在下述 Stage 預排程，決定內容何時取值，不控制何時開跑。

### 整批圖片

把「圖片來源」直接接到資料預排程的圖片或文字接點，即啟動固定清單的自動供應。圖片與文字需要一起固定時，接入同一份預排程。最多十個未結束項目，完成後補入，直到清單結束；再次按執行不會重建同一批。

資料夾預設按檔名自然排序，開始前可在「圖片清單」調整。執行途中新增檔案不會插隊。「停止這批後續供應」停止補入並暫停，已保存項目保留。若來源來自 Stage 結果，使用圖片選單選全部／指定張；固定清單排序先從歷史匯入或改用資料夾來源。

### 排 Stage 或一組 Stage

把 Stage 右側紫色「輸出」接到預排程的紫色「輸入」。B、C 接同一份預排程，就保存 B→C；各 Stage 的流程／圖片依賴仍決定順序。接到預排程表示排程這份流程，不要求先執行 Stage。

在「輸入取值」設定各個 CLIP／圖片輸入的保存／即時方式。保存 Stage 目標、接線及指定 PCS 輸入；模型、尺寸、採樣器等原生參數仍在提交時讀取。尚未產生的 A 圖片保存為「本輪 A 的結果」關係，不存成上一輪的圖片。

| 接法 | 執行結果 |
|---|---|
| A → 三張圖片來源 → B 的資料預排程 → C | B 跑三張，全部完成後進 C |
| B 有三張自動資料預排程，外層排兩個 B | B 共生成 3×2＝6 次；每個外層項目有獨立內層進度 |
| 外層排 A→B→C 兩項 | A₁→B₁→C₁，再 A₂→B₂→C₂ |
| A → 外層排 B→C 兩項 | A 一次，再完整 B→C 兩次 |
| 外層排 B，內層只有手動 Prompt | 一次加入只算一次，不重複乘算 |

可將內層預排程的流程引用交給外層。範圍必須完整包含，不能交錯，例如 A→B 與 B→C 不能成為兩份互相重疊的外層。只有目前外層展開子項，其他項目保留來源及設定。

等待清單可拖曳、移除；雙擊開啟完整內容並修改文字或替換圖片。尚未開始的外層項目也能查看保存的圖片清單、替換指定一張，不改原始資料夾或其他排程項。已提交項目只供查看。圖片張數、項目數與生成次數分別顯示；十項滿額時明確拒絕新加入。

## 最近生成、暫停與恢復

「最近生成」在畫布右下角，打開右側可收合面板。選圖再導入是明確操作，不會讓歷史自動變成 Stage 的輸入。

- 預排程的暫停停止後續派送及補入，已提交工作繼續收結果；從預排程「繼續」恢復。其他保留流程從底部活動任務數打開紀錄處理。
- 取消結束指定 PCS 流程，保留已保存內容與紀錄；不清空 ComfyUI 佇列，不取消其他來源的工作。之後可建立新流程。
- 生成成功、圖片讀取失敗：按底部活動任務數，選實際提交項，再按「重取結果／重試失敗項」只重取圖片。成功後按繼續。
- 明確生成失敗：相同按鈕以原提交內容及種子建立新嘗試。提交結果不明時不自動重送；「查看原任務回覆」取得現有任務狀態，只影響這份流程。
- 生成成功，但未接 Stage 的下游輸入套用失敗或中斷：保留生成結果及同步錯誤，不自動重送。目前沒有只重試這次套用的入口；重新按執行會建立新的生成。
- 更改執行接線時，舊流程未提交的部分保留並暫停；已提交的部分繼續收尾。新的接線可以開始新的流程，不需要先取消舊紀錄。只新增觀看結果的接線不暫停生成；取值策略變更只影響新項目。
- 切工作區、斷線或重開後保留並暫停；恢復原接線與連線後明確繼續。已提交結果歸回原紀錄。已取消的遲到回覆不啟動下一階段，也不套用到新接線。

舊畫布、草稿、綁定、圖片與歷史保留。0.8.3 等待項不轉成新的分層排程；既有 0.8.4 等待項保留並暫停，均不會升級後突然補跑。舊自動追隨 ComfyUI 最新輸出的用途改由 Stage 結果接替。PNG 還原畫布內容，不還原生成任務；Undo／Redo 只改編輯內容。

## 工作流與未存檔內容

使用同版擴充，保持所需工作流在 ComfyUI 網頁中開啟。綁定視窗重新整理後，讀取該原生工作流的草稿節點，不要求先存檔。未開啟、網頁未回覆或擴充尚未更新時，可讀取的存檔會明確標示「已儲存版本」，不當成即時結果；身分歧義或切換失敗則直接顯示錯誤。

PCS 執行另一個已開啟的工作流時，會透過原生工作流切換功能定位它，再套用及提交，保留各工作流草稿；此版本仍需要原生網頁開啟。讀取節點清單只做讀取，不存檔、不推進種子、不生成。提交結果不明時仍保留原任務，不因再次握手而重送。

## 人工驗證清單

請先用小批量測試；以下原生網頁及 GPU 情境須人工確認，離線測試不代替這項驗收。

1. 保留 Stage 卡但拔掉 CLIP→Stage 控制線，按執行只改 CLIP、零生成；接回後，生成中連按兩次，總共三個原生任務，三次文字對應正確。
2. 正、負面及圖片接同一 Stage 只生成一次；混接 A、B 但 Stage 選 A，B 只更新欄位。檢查原生種子模式每次只作用一次。
3. A 三張 → B → C，逐張圖片、文字與輸出節點正確。以「本次 Stage 結果」代替長線，結果一致。指定超出範圍的圖片會明確停在該項。
4. 資料夾十二張直接接資料預排程，最多十項並補完十二張；內層三張、外層兩項共六次。只排 Prompt 的內外層不翻倍。
5. 第一項生成時改正面、負面再加入：已保存正面保留，繞過預排程的負面於提交時更新。拖曳等待項、修改單項及移除後順序正確。
6. 暫停、取消後新工作、斷線重聯、重開、切工作區與遲到回覆均不誤跑。原生 Run 不因 PCS 狀態被封鎖；其他來源任務不被取消。
7. 圖片文字卡不重複輸出；手動空白稿保持空白；預覽選張不改下游；最近生成面板開關不改接線；Undo／Redo 不提交任務。
8. 生成途中插入／刪除預排程，再接一份新預排程；舊提交可收尾，新接線可執行。空閒時按執行不要求繼續；明確暫停後可累積再繼續。預覽與其他模塊均可用 Del／Backspace 刪除及復原。
9. 原生新增第二組正負面 CLIP 而不存檔，重新整理後可選四個欄位。首次執行 Anima、排程耗盡後再次執行、A→B 兩個工作流互換當前分頁，均需人工確認；失敗時保留本輪明確原因，不用反覆取消猜測。
