# Build and release constraints

- `prompt_studio/releases.py` owns release names/flags, launchers, archive names and `SHARED_MODULES`. Generated `BUILD_INFO.json`, manifests and packaged `shared/` derive from those sources and the builders; do not hand-edit generated artifacts to claim another version.
- `build_comfyui.build(destination=..., archive=...)` supports a fresh, task-specific output and archive. Supply both when the defaults could replace a retained artifact; the destination must be empty. Update shared source and the module list, then rebuild the extension. Qt-free import verification is in `tests/test_maintenance_package.py`.
- In versions using `package_documents.source_paths`, packaging reads Git-tracked, allowlisted source from an actual Git root. New untracked files will not be packaged; a copied source ZIP is not automatically a buildable Git checkout. Do not weaken that check to include unrelated local files.
- `SOURCE_MANIFEST.json` covers project sources; `PACKAGE_MANIFEST.json` covers delivered files. Keep source commit, actual executable build commit (`binary_git_head`), extension, version and artifact hashes traceable separately; regenerated docs do not prove an old binary was rebuilt.
- Preserve old program/package/data and use separate staging and test data. Installation/update changes must exercise corruption, redirects/junctions and rollback with disposable fixtures (`tests/test_deployment.py` where present); source privacy uses `tests/test_source_privacy.py`.
- For public redistribution, read [licensing](../LICENSING.md) and inspect the actual bundled runtime, notices and corresponding-source/rebuild materials. Project source and Qt license text alone do not close the executable's distribution requirements. An authorized source-only release does not imply an executable release or permission to replace a user's installation.
