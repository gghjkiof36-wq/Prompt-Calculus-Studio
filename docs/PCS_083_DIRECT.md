# PCS 0.8.3 直接執行修復候選（0928）

本次修正執行方式，取代之前普通操作也在 PCS 等待、暫停與核對的設計。PCS、ComfyUI 服務與網頁均須開啟。

## 操作

- **沒有預排程：**按一次立即提交一次；生成期間仍可繼續點擊，由 ComfyUI 原生佇列接收。次數設 3 就提交 3 次。每次提交採用點擊當時的文字和圖片；提交交接期間的後續修改屬於下一次點擊。
- **接上預排程、目前空閒：**點擊立即提交目前內容，不先建立等待項目。
- **接上預排程、正在生成：**再次點擊才保存接入的內容。當前工作完整完成後，自動執行下一項；未接入預排程的欄位仍在派送時取值。
- **圖片集合：**未接預排程時依點擊次數提交對應圖片；接上預排程時保留整批供應、最多十項及完成後補入的操作。
- **ComfyUI 原生執行：**維持 ComfyUI 自己的操作，不再領取或等待 PCS 預排程。PCS 的暫停、舊紀錄或關閉，均不應鎖住原生執行。

底欄只保留「次數、執行、取消、任務數」。取消顯示為 ×，提示文字為「取消執行」；點任務數查看生成紀錄。預覽仍從畫布的預覽圖片模塊或既有選單開啟，排程的暫停、繼續、排序與內容修改留在預排程模塊。

取消只針對這次 PCS 的指定工作。普通操作已提交的其他項目留在 ComfyUI 原生佇列；預排程中尚未提交的項目會保留並暫停。

## 舊資料

舊版累積的普通點擊不會自動補跑。舊版預排程項目保留完整內容，移到「任務數 → 保留的預排程／舊紀錄」供查看，不會占住新清單或鎖住執行。生成紀錄、畫布、綁定與草稿保留。

「未確認」只是某一筆舊工作沒有完整回覆，不能用來阻擋新的明確點擊。程式不會自動重送那一筆，也不要求先解除它才能執行新工作。

使用本版建立的預排程在手動暫停、斷線或重開後，仍保留等待內容；需要時在模塊內繼續。普通操作不建立可重播的 PCS 等待清單。

## 人工驗證

使用同包 PCS 與 ComfyUI 擴充，替換擴充後重啟服務並重新整理網頁。

1. 不接預排程，連按三次。第一張尚未完成時，ComfyUI 已收到三項；次數設 3 同樣如此。
2. 接上預排程，空閒時點擊 A，應立即開始。生成中改成 B、點擊，再改成 C、點擊；模塊只有 B、C 等待，A 完成後依序生成 B、C。
3. 取消當前 PCS 工作，再按執行，新的工作仍能提交。其它來源任務不能被誤取消。
4. 暫停 PCS 預排程或關閉 PCS，直接在 ComfyUI 按執行，應正常生成，不出現 PCS 要求繼續或核對的攔截訊息。
5. 確認底欄完整顯示四項；點任務數可開啟紀錄，預覽與圖片更新正常。

離線測試涵蓋實際 Qt 點擊、正式提交日誌、服務接收回覆及佇列／歷史完成處理。執行器與瀏覽器為測試替身，不能視為真實 GPU、原生網頁或其他擴充共存驗收。
