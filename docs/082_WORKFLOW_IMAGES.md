# 0.82 工作流順序與圖片綁定

本輪延續 PCS v0.82 Alpha 1，主要倉庫仍為 0.81 的 `6d48f59`，實作分支為 `feature/03-082-panel-layout`。依使用者最後確認：每串 CLIP 選定自己的工作流，接圖不會自動替換工作流。使用者日常資料不作測試或封裝輸入。

## 操作

1. 初次開啟仍提供 Canvas／清單選擇，Canvas 在上並預選；之後保留已選介面。
2. 空白處雙擊，選「功能模組」，可新增畫布、Prompt 輸出、CLIP 輸入、加載圖片、預覽圖片或工作流順序。
3. 將画布連到 Prompt，Prompt 連到 CLIP。點 CLIP 內的選擇按鈕，先選工作流，再選其中可綁定的 CLIP 文字節點。相同欄位不重複占用；沒有綁定的原文字保留。
4. 加載圖片可以手動選圖，或點選工作流→LoadImage／PreviewImage／SaveImage 節點。可先留空、稍後設定。關閉「顯示圖片」仍保留選擇按鈕與圖片輸出接點。改用手動圖會解除該模組的節點綁定；解除節點綁定可回到原手動圖。
5. 圖片可接入預覽圖片左側，或接入 Prompt 左側圖片端口。工作流接收圖片的 LoadImage 欄位仍在既有「設定→ComfyUI→工作流管理」設定。已接圖但沒有可用圖片／接收欄位時，停止並提示，不悄悄改跑其他工作流。
6. CLIP 工作流選擇旁的數字可改順序；「工作流順序」模組可拖曳排序。兩處共用資料。排序模組只有工作流清單，沒有端口、Prompt 結果或執行鈕。同工作流的正、負面 CLIP 共用一個排序位置；新加入的工作流排在既有工作流後。

只有 A 的文字串時只執行 A。若 A 文字串與 B 圖片＋文字串同時存在，一次執行依序完成 A、B，各提交一次；執行次數設為 2 就是 A→B→A→B。B 的加載圖片綁定 A 的輸出節點時，等同輪 A 完成，再使用該次實際任務的圖片。

只有 B 的 CLIP 串、加載圖片讀 A 時，不會因為圖片綁定而額外啟動 A，會讀 A 已有圖片。排序把來源工作流放在後面時，也只能使用該來源先前已有的圖片；沒有可用圖片即停止。執行順序依使用者排序，未加排序模組則按綁定成立先後。

執行列顯示本輪與已完成工作流數；執行中的 PCS 串以藍框標示。工作流內的節點編號來自既有狀態輪詢。進度是已確認的工作流完成數，不是採樣步數百分比。

## ComfyUI 擴充與圖片來源

桌面與同版 ComfyUI 擴充須一起更新；安裝包中的 `comfyui_prompt_calculus_studio` 放入 ComfyUI 的 `custom_nodes`，保留原私人設定／資料，更新後重啟 ComfyUI 並重新整理瀏覽器。本輪只交付包，不自動操作 ComfyUI 或 GPU。

如需同步瀏覽器目前節點圖片，從 ComfyUI 的 PCS 側欄將該工作流「匯出到桌面」，或另存 PCS 工作流交換檔再匯入。這個流程保存穩定工作流 ID，允許跨工作流區分相同節點編號。單純匯入舊 API JSON，尚未對應瀏覽器工作流時，LoadImage 只能先用該檔保存的圖片參照；介面提示其來源，不能視為已同步瀏覽器。

一般讀圖比較該工作流瀏覽器目前選圖與已完成紀錄；新的完成結果優先於較舊的輸出縮圖，LoadImage 則使用當前選圖。A→B 的同輪交接明確指定 A 的 `prompt_id`，不被舊瀏覽器縮圖替換。節點輸出多張圖且無明確選擇時，提示使用者在 ComfyUI 選一張，不自行挑選。讀取只接受 ComfyUI input/output/temp 內的檔案，複製為本機不可變圖片參照後傳給下游。完成時間取自 ComfyUI [execution.py](https://github.com/Comfy-Org/ComfyUI/blob/master/execution.py) 的 execution_success 紀錄；實際安裝版本仍需外部驗證。

## 工程資料與相容

- `multi_output` 內部 3→4；外層文件與快照仍為 4。新增每個 CLIP 的所選工作流、共同工作流順序、圖片節點綁定與顯示選項。舊文件載入沿用原 `prepare_state`、備份及驗證入口。
- 舊 CLIP 多工作流對照保留；第一次遷移優先選該 CLIP 原先的當前工作流，沒有則選第一個已存綁定。每個 CLIP 同一時間只執行所選工作流，其餘對照不自動加入執行。
- WorkflowRun 建立執行開始時的 Prompt、工作流、排序、手動圖片快照，沿用 GenerationRunner 的工作日誌與 ComfyClient 傳輸。已送出任務的真實 prompt_id 確認完成後才開始下一步；取消、斷線、失敗或未確認提交停止後續步驟，保留可查紀錄，不自動重送。
- 圖片刷新使用只供顯示的投影，不改手動稿／undo。執行中的動態來源只寫入該步快照；歷史記錄保存該次實際提交內容。
- Qt-free 共用模組增加 workflow_flow；node_images 在擴充端解析節點圖片，沿用 loopback／同源／Token 檢查。能力旗標 `workflow_images_v1` 用來拒絕舊擴充接收新流程。
- 搜尋快取已於 `abd1f40` 實作；容量、停用／清除與舊回應拒絕規則見 `082_FLOW_CACHE.md`，本輪持續驗證。未新增依賴、平行資料庫、全域設定或模型。
