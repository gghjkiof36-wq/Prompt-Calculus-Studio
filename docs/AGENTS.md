# Documentation evidence

- Describe the fixed version covered by the evidence. A roadmap, old technical contract or visible preview is not proof that a capability is shipped; a source/package hash is not an installation or GPU test.
- Keep current state in the relevant version/status record and link to it. Do not append a new “current” paragraph beneath contradictory old ones without marking the old material historical.
- Public docs must stand alone without local task IDs, private paths, credentials, private reviews or user images. Name the tested version of screenshots and the limits of reported results; do not invent adoption figures or CI badges.
