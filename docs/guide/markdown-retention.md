# 保存演示、查回對話與可攜匯出

適用：0.8.9 Beta3 本機開發版 · [貼上與對話匯入](markdown-import.md)

本版提供演示原件保存、原問答查回、人工 ChatGPT 整理往返，以及所選文件的資料夾／ZIP 匯出。ChatGPT 登入串接另排；PCS 不會自動傳送內容或宣稱已完成自動摘要。

## 加入演示與原檔

1. 在 Markdown 編寫／原文模式，把游標放到要加入的位置。從插入選單選 **演示／原檔**，也可在命令搜尋找「加入演示／原檔」。
2. 填標題，選原檔、靜態預覽或來源網址。HTML 演示有 CSS、圖片等檔案時，選包含入口原檔的專用依賴資料夾；裡面的檔案都會保存，先確認選取範圍。
3. 按 **預覽保存內容**，查看實際檔案、大小與缺項，再按 **保存並插入**。
4. 閱讀時看到的是提供的靜態圖片與普通 Markdown 連結。按原檔連結才交給外部程式開啟；PCS 閱讀不執行 HTML／SVG，也不下載遠端引用。

可以只保存預覽或來源網址。正文會標示尚無原檔，之後從「附件與修訂」連結補入。已知的缺檔、外部網址及無法分析的動態依賴會列出；靜態掃描通過不代表整個專案能離線運作。

每次保存都建立新附件資料夾。插入／替換引用可一次 Undo／Redo；復原不刪附件或歷史修訂。原件被移走或改內容時，開「附件與修訂」核對狀態、重新指定，再建立修訂。修訂保留上一版，只有目前這段正文引用會更新。處理中若改了文件、切頁或進入閱讀／組字狀態，完成結果不會插到新的位置；已完成的附件仍保留。

## 查回當時的問題與回答

從 Markdown 右上角 **⋯ → 查回與整理對話…** 開啟。匯入對話資料夾中的文件會自動找到 `原始對話.json`；也可以手動選擇目前筆記根內的原始紀錄。純貼上文字不會被猜成完整歷史。

在「原問答」選分支，以關鍵字、角色或日期搜尋。日期使用 UTC，起迄日均包含。預設查目前分支與共同歷史；「全部分支」會合併共同訊息，並標出所屬分支。選結果後查看當時的問題、回答與上下文；該分支沒保存回答時會明說。這裡顯示保存的原文，手改分支 Markdown 不會改寫歷史。

搜尋每頁顯示 200 則。上下文顯示上限為 200 萬字元，超過會提示；完整內容仍在原始紀錄。可釘選目前分支中必須原樣保留的訊息。

## 複製到 ChatGPT，再貼回核對

1. 到 **ChatGPT 往返**，選「接續工作／閱讀整理」、長度與每段字元數，按 **準備整理內容**。內容包含所選分支及共同歷史，不包含其他分支回答。
2. 選第 1 段，按 **複製本段**，自行貼到 ChatGPT。按每段附帶的要求取得 JSON 回覆，再完整貼回 PCS，按 **核對引用並加入候選**。依序處理其餘段落。
3. 回覆必須保留本次 `request_id`、段次及來源訊息 ID。格式、請求身份、段次或引用不符時不採用；已收到的段落不會被再次貼回的結果覆蓋。保留畫面中的回覆，修正後重貼即可。
4. 到 **候選與接續**，逐項核對「人類已明確決定」「AI 建議」「要求／限制」「已取代方案」等分類。雙擊內容可修改；雙擊來源訊息可查原問答。確認語意後勾選「已核對」。修改項目會清掉該勾選。
5. 設定接續內容上限，按 **組成接續內容**。輸出包括分類結果、核對狀態、釘選原文與引用原文，可繼續手改，再複製、另存 MD 或 **另存新版本**。

分段按字元計算，預設每段來源文字 16,000 字元；這不是模型 token 上限，複製內容還包括指示及來源資料。模型無法接受時，降低每段字元數重新準備。超長單則訊息也會按原文位置分段，沒有靜默截斷。尚未收齊段落的候選會標明只整理部分範圍。

來源引用通過只表示身份與位置有效，不能證明 ChatGPT 的理解正確。PCS 不會自行把建議變成定案，也不執行歷史內容中的工具要求。使用者實際選用的 ChatGPT 模型不由 PCS 驗證。

釘選原文及引用原文可能很長；超過上限時會要求調整，不自動刪除。手改稿若漏掉釘選原文，複製、另存 MD、保存新版本都會阻止。改分類或引用後須重新組成；先複製保留額外手改文字，再合併回新稿。

「另存新版本」在原始對話旁建立 `整理稿/<新版本>/`，保留 `整理.md`、候選項目、範圍內原始紀錄與可取得的附件。再次保存另建版本。載入舊候選會保留其實際手改文字，來源更新或分支不同會顯示狀態；要重新整理請另開視窗建立另一份候選，保存版本可分頁比較。沒有自動差異合併或背景重新生成。

## 匯出與重新開啟

1. 開啟要帶走的 Markdown，選 **⋯ → 匯出文件與來源…**。採用開啟匯出視窗當下的編輯內容，包含尚未保存的文字；之後繼續編輯不會混入本次快照。
2. 選資料夾或 ZIP。對話可選單一分支（含祖先）或全部分支；整理稿可包含來源與修訂資料。正文若含另一分支的可辨識訊息，需改選相符範圍。整理稿來源不符時，選對來源／分支或取消附帶整理追溯資料。
3. 按 **預覽匯出內容**，核對實際檔案及缺項，再選位置匯出。每次建立新輸出，不覆寫原筆記、舊包或既有手改稿。
4. 資料夾可在 PCS 加入為筆記根，從 `閱讀說明.md` 開入口；ZIP 使用 **⋯ → 開啟可攜 ZIP 副本…**，選副本位置。驗證完成後建立新根並開啟入口。再次開同包仍建立獨立副本。

包內保留普通 Markdown、相對附件與清單，不依賴舊 PCS 資料庫。一般 MD 閱讀器可讀基本內容；PCS 提供額外的演示管理與對話追溯。來源 JSON 明確標示為所選範圍擷取，不能當作完整原封存。

只匯出目前文件、引用附件、嵌入的普通筆記，以及明確選取的對話範圍。一般連到其他筆記的連結不自動擴大範圍，會列出未帶入項目；遠端內容也不下載。分享前仍須檢查所選原文與附件本身的私人內容。

## 取消與限制

處理中可取消，關閉視窗也會提出停止。檔案工作在可中斷位置結束；取消受理不代表正在進行的單次寫入已立即停止。未完成資料夾／ZIP 保留供核對，沒有有效的 `保存完成.json` 就不算完成；重試建立另一份。來源、目標資料夾被替換或內容混合修訂時，操作會停止。

單檔上限 256 MiB，單次總量 512 MiB、最多 2,000 檔；依賴資料夾最多選 1,990 檔以保留描述檔空間。這些是拒絕界線，不是已驗證的流暢容量。未知格式、執行檔不直接開啟；可從附件資料夾自行管理。[本版驗證與限制](../releases/0.8.9/validation/beta.3.md)。
