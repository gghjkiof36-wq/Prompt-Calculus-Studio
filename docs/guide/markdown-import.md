# 貼上格式與匯入對話

這份說明適用於含「匯入對話…」入口的本機開發試用版；已公開的 Alpha 1 不因此新增這些功能。

## 貼上回覆或網頁文字

在 Markdown 的編寫或原文模式按 **Ctrl+V**。PCS 優先使用剪貼簿中的 Markdown，其次轉換 HTML，最後使用純文字。標題、粗斜體、巢狀清單、待辦、引用、一般表格、程式碼與可取得來源的公式會保留成可編輯文字。來源網站的按鈕與工具列不會一起貼入。

貼上只替換目前選取的內容；沒有選取時插入游標位置。**Ctrl+Z** 可一次復原，**Ctrl+Y** 可重做。文件沿用原本的自動保存，也能按 Ctrl+S 保存後重開。

較大的 HTML 會先顯示「正在整理貼上內容…」。整理期間可以切換分頁；內容仍屬於原文件。若原文件或編輯模式已改變，PCS 會保留你的修改，請回到適當位置重新貼上。閱讀、唯讀及中文組字期間不插入內容。

只想貼原來的文字時，使用 **Ctrl+Shift+V**。損壞或過大的 HTML 轉換失敗時，文件與剪貼簿保留，可改用這個方式或分段貼上。剪貼簿圖片沿用本機附件保存。

| 來源情況 | 處理方式 |
| --- | --- |
| 一般表格 | 轉為 Markdown 表格，保留欄對齊及格內換行 |
| 合併儲存格／巢狀表格 | 保留安全的表格原文，附上說明；不猜測欄列 |
| 有 LaTeX 的公式 | 保存公式來源；同時存在的視覺副本不重複貼入 |
| 只有公式外觀、沒有公式來源 | 保留取得的文字，無法重建未提供的 LaTeX |
| 遠端圖片 | 保留可用連結；貼上時不下載。沒有可用連結則顯示說明 |

## 匯入 ChatGPT 對話

1. 開啟一份 Markdown 文件，點右上角 **⋯ → 匯入對話…**。也可以在文件命令搜尋中找「匯入對話」。
2. 將本機 ChatGPT ZIP 或 JSON 拖進視窗，或按「選擇檔案…」。載入後才顯示對話清單與預覽。ZIP 內需有 `conversations.json` 或編號分段檔，例如 `conversations-1.json`。
3. 搜尋標題，勾選需要的對話。點擊清單文字只預覽；勾選方框才加入匯入。預覽可以切換分支，實際匯入會保存所選對話的所有分支。
4. 確認「儲存至」的位置，再按 **匯入 N 段**。預設位置是開啟入口的 Markdown 所在資料夾。
5. 完成後，PCS 會開啟第一份對話索引；從索引開啟各分支與支援的媒體附件。按「開啟資料夾」可以查看原始 JSON、其他格式附件及全部結果。

預覽只顯示開頭一部分，會註明預覽到此；匯入不因此截斷。視窗變窄時，清單與預覽改為上下排列。整個過程使用本機檔案，不登入帳號或自動下載附件。

## 保存後的內容

每段對話各有一個新資料夾，包含：

- `對話.md`：標題、全部分支／分卷連結、附件及缺失說明。
- `分支-001-001.md` 等文件：每條路徑的共同歷史與該分支回答，按訊息先後排列。
- `原始對話.json`：所選對話的原始欄位、訊息及關係；JSON 排版會重新整理，內容資料保留。
- `assets`：能明確對應且封存內確實存在的附件。
- `匯入開始.json`／`匯入完成.json`：供程式判斷完成與重複匯入的紀錄。

來源 ZIP／JSON 不會修改，未選對話不會複製至目的位置。編輯匯入後的 Markdown 也不會更動原始封存或原始紀錄。未知的訊息類型會留下說明，可回查原始 JSON。

同一內容再次匯入到相同位置會略過，保留你改過的筆記。來源更新則另建一份，不覆蓋舊版。附件缺失或有多個可能對應時，索引會列出原因；不會猜測或自行下載。

## 取消、失敗與容量

處理中按「取消處理」或關閉視窗，會先顯示正在停止，直到工作到達可安全停止的位置。已完成的對話保留。中途失敗的資料夾保留開始紀錄，但沒有有效的完成紀錄；重試會另建資料夾，不覆蓋殘留或手動編輯。

目前來源上限為 256 MiB，ZIP 展開總量與單次輸出上限為 512 MiB；最多 10,000 段對話、100,000 個訊息節點，每段最多 2,048 個分支。大量共用歷史也會計入輸出容量。長對話按約 7 MiB 分卷；超長單則訊息以分段 Markdown 原文保存，索引可到達各卷。超額會明確拒絕或保留未完成紀錄，不靜默裁切。

本機合成資料與 Windows 操作流程已做範圍內檢查，尚未以真實帳號匯出逐項驗證。大型貼上採分段插入，仍可一次復原；保存或關閉時會先完成整筆插入。不同長文件與匯出格式的效能仍持續追蹤。
