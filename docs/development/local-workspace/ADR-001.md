# ADR-001：本機文件、內容歸屬與多視圖邊界

日期：2026-10-17。狀態：P0 設計與合成盤點已經需求主責核對；P1 文件核心已實作，交階段核對；P2 尚未放行。實際格式、API 及限制見 [SCHEMA](SCHEMA.md)，完成證據另依各階段檢查點。

依據：本機分頁工作環境分階段規格 W01～W30。核對來源固定為 `2b72f6042cac4c4104256a93f6ff66e7b1be6809`。P0 的目的是把既有契約對應到可開始的文件核心；P2～P6 的細部實作由各階段補齊。[P1 工作順序](P1-PLAN.md)、[既有資料契約](../data-compatibility.md)。

## 決定摘要

1. 分類及工作流文件保存內容真相，沿用現有素材樹及狀態驗證。MD 保持普通 UTF-8 檔案。
2. 一個素材原件只有一個分類文件擁有；組合、素材流程及 Canvas 的內嵌內容仍是獨立副本。來源資訊可追溯，不構成持續同步。
3. 一份工作流文件承載一個完整 PCS workspace 場景與其必要 graph／profile 閉包，包括多個內部 Canvas。不能把內部 Canvas 或 ComfyUI profile 各拆成一份文件而遺失線路。
4. 每份開啟文件有一個 canonical DocumentContext；同文件雙視圖共享該 context，不同文件各自持有 state、交易、Undo、保存器與事件身分。
5. SQLite 繼續保存設定、內容歷史、生成任務、journal、回執與資產目錄等責任；只有新文件索引可以重建。P1 不接 live 任務，不改 journal。
6. 舊「移除分類並保留素材」與新「將文件移到資源回收筒」是兩個不同命令，兩者能力都保留。

### 已用合成反例確認的事實

[`tools/local_workspace_p0.py`](../../../tools/local_workspace_p0.py) 建立 3 分類、5 素材（含三種類型）、跨分類嵌入組合、流程輪次及多變體；2 個 workspace，各有 2 個內部 Canvas，2 個綁定、不同鏡頭／草稿、手動空字串及已保留 repeat=1 的 Reader。

- 移除跨分類來源原件後，內嵌組合仍渲染原內容，既有 Canvas 副本不變。這證明不能把 source_id 一概當成必須 live 解析的依賴。
- `materials.remove_category` 將所屬原件轉到未分類，素材 ID／副本／空稿保留。
- 兩個假視圖若直接指向同一 state，呼叫 `workspace_scene.switch` 後兩者都看到新 workspace；這是不能拿全域 current state 假裝多文件的具體反例。
- `snapshots.portable_state` 省略 pinned 與 content_history。PNG 生成投影不能直接充當可編輯文件 serializer。
- 既有 JSON 與 SQLite 保存／關閉／重開可完整比較；兩筆合成 journal 行保持。此證據沒有測試新文件 codec、Qt 分頁或執行結果。

## P1 文件封裝決定

副檔名採 `.pcs-category`／`.pcs-workflow`，UTF-8 結構化 JSON。外層 `file_schema_version=1` 與現有 `state.version`、PNG `schema_version`、formatter_version 完全分開。

外層欄位：`format="pcs-document"`、`kind`、`file_schema_version`、`document_id`（UUID）、`revision`（id／parent）、`payload`、`assets`、`extensions`。外部 `LoadReceipt` 保存讀取時原始 bytes SHA256／檔案身分，用於寫入 precondition；避免把含自身的 raw hash 寫入同一物件。revision 與檔名／mtime 分開。

分類 payload：完整 category record＋有序 owned items 陣列。items 順序就是該分類的手動素材順序，不設另一份同義排序真相。內嵌 composition、變體、輪次、取消時保留的 inactive 內容及來源資訊原樣保留。驗證時將這個 payload 裝入最小 legacy-state wrapper，呼叫現有核心驗證器；wrapper 不是另一份保存來源。

工作流 payload：一份限定單 workspace 的已驗證 legacy state，包含 scene fields、該 workspace metadata、必要原件定義閉包、profiles 與內容相關設定。`modules/items` 中供舊 list 或來源追溯使用的定義標為 `pinned_dependency`，不成為第二個可編輯原件。`workspace_scenes` 的活動重複 cache 可由 adapter 重建；不收錄其他 workspace 場景。必要未選中輸出、未連線內部節點與其完整副本仍屬內容，不得用 selected-only 篩掉。

設定採明確欄位分工：影響組合的 formatter／artist_prefix／separate_selections 等跟隨內容；外觀、網路開關、模型根路徑、憑證、安裝偏好屬本機設定。P1 建欄位責任表及漏欄負例，不將 `settings` 整包當作可攜內容，也不靠預設值掩蓋未知的內容設定。

新增可選欄位放 namespaced extensions；已接受的可選資料往返保留。未知 kind／版本、未知必要語義或不合法結構明確拒絕寫入，保留原 bytes，不能用空模板覆蓋。現有 payload 中允許的可選欄位深複製保留；不得沿用 PNG 的刪欄白名單。拒絕循環／超界 JSON，沿用核心型別、深度、數量驗證並加檔案位元組上限；不靜默截斷內容。

### 原件、依賴與 ID

- canonical reference 是 `(document_id, entity_id)`；legacy ID 保留在其文件作用域。document registry 以文件身分管理，不以顯示名稱當鍵。
- 跨分類的完整嵌入副本只帶 provenance，不需要當前來源原件才能渲染。已知來源可記文件／分類／素材 ID 與 revision，無可解析來源時標 unresolved provenance；不能為了補連結偷讀其他根。
- 舊 list 等真正需要原件定義的參照保存版本固定的唯讀依賴閉包；排除未引用原件，來源改動不自動替換這份定義。同一原件可出現在其他文件的唯讀快照中，不能同時註冊成第二個 writable owner。
- 改名／搬移保持 document ID、內部 ID、revision lineage；明確獨立副本建立新 document ID，經完整映射更新擁有內容的內部 ID／references，保留出處。僅使用 `comp.clone_node` 不足以複製整圖，必須包含 Canvas／output／clip／Stage／Reader／scheduler／群組與游標簽章。P1 將共享 catalog 的 profile 明確標為 pinned dependency：profile 及其 ComfyUI graph 節點、server、frontend、目標欄位識別保持，不註冊成第二個可寫服務身分。唯讀依賴與 provenance 不混同文件擁有內容 ID。
- 同 ID 的外部複製文件若出現在另一實體路徑，先列為身分衝突，不默默同開兩個可寫模型。明確「建立副本」才重建身分；硬連結／同實體檔同視圖共用 context。

### 附件與可攜性

附件採文件所在目錄相對路徑，置於一般 `assets/<document-id>/` 目錄，可依 hash 去重。manifest 記邏輯 reference、實體相對 path、SHA256、大小及型別。P1 保留 shared validator 要求的 `originals/generation/...` 邏輯來源，以 manifest 映射到資產實檔，避免改素材定義而使已保存的游標簽章失效；透過 `assets.resolve` 解析。整個文件根搬移後仍能解析，不能依賴原 DB 路徑。

需要覆蓋 item／node preview、generation.source、canvas_functions.images、Canvas image layer 等已知路徑位置。模型名稱、伺服器可用性、缺失的外部檔案明列依賴；遇不能安全轉成相對附件的必要來源，不得宣稱可攜完整。圖中未知帶路徑欄位不得用廣泛字串替換破壞語義；保留待處理內容並給出具體未支持欄位。

檔案解析限制於明確接入根及其附件基準，拒絕絕對路徑逃逸、`..` 逃逸、重解析點跨界及目錄循環，不掃其他根或 `.obsidian`。文件索引／樹序／分頁狀態可放 `.pcs`，唯一素材內容不得放在索引。新文件 wrapper／索引／私人絕對路徑不傳入生成 metadata；生成仍走既有必要投影及隱私邊界。

## 安全保存與 P1 邊界

讀取回傳 model＋LoadReceipt；保存必須驗證候選、檢查 expected receipt、新 revision，寫同目錄唯一暫存並 flush，再走平台安全替換。新建使用不覆蓋語義；名稱與路徑規則由核心 I/O 邊界驗證，包含 Windows 大小寫、保留裝置名、尾端點／空白、同一路徑及根範圍。

寫入失敗／衝突時保留舊內容與 dirty model；UI 尚未建立，不假稱已有衝突對話框。安全替換產物、回復副本及結果需可辨識，禁止在未知狀態下自動重試覆蓋。P1 先完成單文件、合成附件、revision 和失敗注入，不實作檔案回收或跨磁碟資料夾移動（P3）。

**競態不能略過：**「讀 hash → os.replace」有外部編輯器在兩者之間寫入的窗口，mtime 或 PCS 內部鎖也不足以保護非合作寫入者。依規格 5.4 澄清，一般替換前失敗維持原路徑不變；若在替換時才偵測競爭，允許將外部版本及候選完整保存在明確可取回的回復檔，回傳衝突／待處理、維持候選 dirty，不自動重試覆蓋，也不顯示保存成功。P1 須以 Windows 原件／替換備份機制及競態注入證明兩版本保留；若無法保留兩份則阻擋寫入。這是可回復安全替換，不能聲稱完整 CAS。P0 未驗證該平台機制。

## SQLite 與執行責任

| 責任 | 既有資料 | 決定 |
| --- | --- | --- |
| 舊完整庫／設定／內容歷史 | Storage.document、content_history、workspace.history | 保留。新文件成為新模式內容真相；本地歷史與全域設定分離責任，但不刪舊 document 或歷史。 |
| 生成／排程 | stage_journal、generation_jobs、input_queue/control、work_queue、chain_* | 持續使用既有引擎與保存值；導入、開頁、關頁均不得建立或重送任務。 |
| 本地使用與回饋 | usage、accepted | 正式資料，保留 workspace／文件歸屬映射。 |
| 資產／回執／草稿 | resources、asset_sources、workflow_receipts/deletions、stage_editor_local、clean_* | 沿既有責任；圖片歷史與暫存可否重建分別判斷，不整批稱 cache。 |
| 可重建資料 | cache/cache_access、新 document index | 新文件 index 可刪後重建；重建不得去刪其他 SQLite 表。 |

`StageStore.transaction` 與 `StageRunner.reserve_supply/accepting` 目前將供應進度和 journal 用同一 SQLite 交易保存。分檔後不能直接把其中 `store.save` 換成檔案寫入而宣稱仍具原子性。P4／P6 須補跨介質 intent／revision／回復協調：任何可派送任務都對應已接受的凍結內容及進度；中斷可對帳、不重複消耗、不以目前 state 重算歷史、恢復不自動送出。這是後續出關約束，不是要求 P1 先重寫 journal。

## 文件與雙視圖 context

既有 Window 的 state／store／save_timer／canvas_edit_context／ChangeCoordinator／Jobs／ComfyClient 及 MultiCanvas 多處經 `window.state` 操作，是必須顯式適配的邊界。`workspace_scene.switch` 只能處理某個 context 內的狀態載入，不能當不同分頁共用全域 state 的開關。

- AppServices：本機設定、服務連線、歷史 DB、全域 job registry 與資產服務。頂部連線狀態屬此層。
- DocumentRegistry：`document_id → DocumentContext`，協調實體路徑／revision／同身分重複路徑。
- DocumentContext：自己的一份 state、內容 Undo／Redo、dirty／save transaction、變更協調與事件 epoch。category 與 workflow context 的 writable owner 分開；不從「最後活躍 Canvas」推測操作目標。
- ViewContext：view_id／document_id／pane／view kind／瀏覽或保留；保存自己的鏡頭、捲動、選取、焦點與暫存 UI。關一個 view 只釋放 view，尚有其他 view／任務時不銷毀必要 context。
- ExecutionContext：固定 document/workspace/server/workflow/run/operation 身分及凍結輸入。回呼寫入其原 context／journal，再通知仍存在的對應 view；不能讀焦點分頁決定歸屬。舊 journal 的 workspace ID 對照在 P6 明確導入，不直接改舊行。

適配從 P2 的單區骨架就以固定 context host 傳給既有元件，不能先建立暫時全域切換而把危險留給 P4。P4 再完成雙區與多文件提交驗證。既有 `TextCanvas.commit`、`MultiCanvas`、RunControls 與生成引擎保留；必要重構是變更 owner 入口，不是第二套生成實作。

### 原生文字 Undo 的具體承接

基準 `_key` 是 source item ID 或 canvas workspace／target；cache 掛在 Window。新 key 至少加入 document_id，cache 與原生 document 由 DocumentContext 持有。原生 QTextDocument 是唯一 Undo owner；不能靠 setPlainText 或 clone 重造歷史。

同一內容雙視圖沿現有單可寫 view 契約做焦點租約：取得輸入焦點的 view claim canonical QTextDocument，另一 view 顯示其最新唯讀內容；焦點轉移保留原 document、游標／selection／scroll。兩個 view 隨時可切換編輯，避免各有可寫快照互相覆蓋。modal 編輯沿 ModalNativeHistory 的暫時交易／Cancel rollback，不讓第二 view 在交易期間暗改來源。P4 必須以真 Qt 的輸入、焦點、Undo／Redo、取消證明；P0 僅確認來源契約與適配方向。

| 中央「移除分類並保留素材」 | 保留原件及使用副本，原件轉入未分類 | 沿舊 remove_category 語義。文件模式以可回復內容轉移交易承接：先可靠保存接收分類，再退役原分類；失敗維持原狀。未分類只在需要承接內容時存在，不成為根的固定上層。跨文件交易在 P3 實作與核對。 |
| 側欄「移到資源回收筒」 | 將這份分類／工作流／MD 實檔回收；分類包含所屬原件 | 獨立檔案命令，顯示影響內容與 dirty view；成功才移出索引。保留 Canvas 副本，出處可標不可取得。不可偷偷改成舊分類解散，也不可讓舊 handler 變成刪素材。OS 回收不可用就保留，不改永久刪除。 |
| 根「移除資料夾連結」 | 導覽移除該根 | 不刪檔、不清內容或任務。 |
| 關視圖 | 關分頁 | dirty／最後 view 處理沿文件契約；不等於回收或取消任務。 |

## P6 舊資料導入原則

先 dry-run：列每分類與 workspace、完整來源身分、跨分類依賴、資產、缺失／名稱衝突，輸出穩定映射與 hashes。預設分類一檔、workspace 一整圖檔；舊單層邏輯 folder 可映射真目錄，無對應收納的分類可直接在根。

從副本轉換、先驗證再公開文件集合，重複導入依原庫識別／實體 ID／修訂映射處理，不靠名稱去重。原 DB／歷史不刪；失敗可回復導入清單。文件取得內容不等於自動接續舊任務；歷史與執行身分遷移須另有明確對照及驗證。

## 階段影響與未驗

P0 只新增本 ADR、P1 清單與合成盤點工具；產品與既有測試不改。P1 新增 Qt-free 文件模組及對應測試；P2～P5 分別適配 shell/context、檔案操作、雙 Canvas／執行歸屬、MD；P6 才整合隔離導入。詳見 [P1-PLAN](P1-PLAN.md)。

Impeccable Operate 用於核對操作密度、一致性與原生約定。context loader 沒找到 PRODUCT／DESIGN；實際 Qt 來源仍是既有視覺與操作依據，不能把工具的未識別當作沒有介面。P0 不改畫面；P2 前按已確認規格與同版真畫面完成需要的 surface context，補充技能只處理具體缺口。

P1 已驗新 codec、附件搬根、單檔安全替換及競態回復；詳見 SCHEMA 與 P1 檢查點。文件與 journal 整合、真正雙視圖原生 Undo、多文件回呼及 Windows 拖放尚未實作，分屬後續階段。文件核心結果不冒稱分頁 UI、完整會話可攜或前置修正已取得獨立接受。
