# Markdown 文件關係（D）

D 在既有 Markdown 編寫、閱讀與共用保存底座上加入筆記連結、嵌入、屬性及位置變更時的引用協調。原生操作與使用者接受仍待驗；筆記搜尋／管理（E）與復原／完整整合（F）另列，不能把本批當作整個 MD 1-1 完成。

## 使用

- 工具列的插入選單提供「連結」與「筆記嵌入」；`Ctrl+K` 開啟連結草稿。可以填筆記名稱、相對路徑、別名、`筆記#標題` 或 `筆記#^區塊`。在編寫區按 `Ctrl+Enter` 或 Ctrl 點擊開啟游標處連結；閱讀區直接點擊。
- Wiki 連結如 `[[人物/林澈#動機|林澈的動機]]`，Markdown 連結如 `[書店](場景/舊書店.md#^late-room)`。同名目標無法確定時顯示位置選擇，不默選任意檔案。
- `![[人物/林澈#動機]]` 嵌入標題下的內容；`![[場景/舊書店#^late-room]]` 嵌入區塊。嵌入標頭可回來源；同工作區來源稿或磁碟更新後，閱讀畫面重新呈現。
- 文件選單／命令中的「筆記屬性」，或 `Ctrl+;` 開啟屬性草稿。支援文字、清單、數字、核取方塊、日期、日期與時間及標籤；`aliases`、`tags`、`cssclasses` 保留其清單語意。每列直接編輯名稱與值，左側型別圖示可變更型別或移除；清單以可編輯標籤呈現，新增列須有名稱。
- 套用連結或屬性為一筆編輯交易，可以一次 Undo／Redo。取消不寫入；開啟草稿後正文已變動時，拒絕套用過期內容。
- 側欄既有改名／搬移與文件另存入口會協調 Markdown 引用。更名／搬移更新入站、出站與所有開啟視圖；另存只調整新文件的出站相對引用，原檔與指向原檔的連結保持。

## 保存與呈現邊界

引用更新只替換目的地字串，保留標籤、標題／區塊片段及無關原文。程式碼、註解與 YAML 裡的文字不冒作正文連結。基本屬性表單只改明確編輯的區段，未知巢狀值、自訂 YAML tag、重複鍵等顯示為原文保留，可回原文模式修改；不透過全份 YAML 序列化改寫文件。

搬移前核對磁碟與未保存草稿；逐檔使用比較後的安全寫入，暫停相關自動保存，並保留操作前後的引用副本。一般寫入失敗會嘗試回復自己已寫入的內容；若同時出現無法安全回復的外改，保留原稿並告知復原資料的位置。這不是斷電後的完整交易恢復功能，後者仍屬 F 的整合驗收。

嵌入在目前資料根內解析，排除 `.obsidian` 與檔案系統連結；不自動執行筆記內的程式或載入遠端資源。已存在的遠端資源仍需明確按下載入。外部網址僅在明確點擊後交由系統開啟；檔案連結只接受既有 PCS 文件與支援的媒體類型。

筆記嵌入最多 4 層、32 次展開，單份嵌入來源最多 512 KiB，單次呈現累計來源最多 1 MiB；循環、遺失、過大或超過預算時保留可理解的狀態及來源入口。這些限制避免小型重複引用膨脹成大量畫面，不代表真實大型 Vault／接近 8 MiB 文件已完成效能驗收。

## 透明度設定修正

材質與透明度預覽改為更新視窗材質與必要重繪；不再每個滑桿刻度重新套用整個工作區的樣式。相同配色／字型樣式不重複套用，材質選擇未改變時也不重複呼叫原生 backdrop 設定；保存既有預覽值不再觸發第二次全域排版。

隔離 offscreen、同樣 783 個 widget 與字型的比較中，透明度步進平均由 296.46 ms 降至 1.71 ms，最大值由 378.63 ms 降至 5.85 ms；測試期間完整樣式套用由 63 次降至 0 次。事件迴圈最大間隔仍有 141.85 ms，因此不能據此宣稱所有操作皆維持 60 fps。實際 Windows 合成、DPI 與操作手感待原生試用確認。

### D-r2 啟動材質與編寫版面

原生材質改在視窗顯示後套用；首次顯示或原生視窗重建時會清除材質快取，準備完成前使用實色底，避免把初始化中的清晰透明誤當成已保存的 Mica／Acrylic。透明度滑桿仍只更新重繪，不重套全窗樣式。

新增「透明 · 清晰背景」，讓清晰透出背景成為可保存的材質選擇；其透明度獨立於 Mica、Acrylic，0 為完整底色，100 為完全移除框架底色。正文與設定表單維持可讀的實色表面。此選項與 Windows Acrylic 的模糊材質分開，不改變既有設定；舊資料缺少新欄位時補入預設值 20。

文件工具列保留適度間距，依內容寬度在編輯欄中置中；窄欄多餘功能仍由右側箭頭開啟圖示格。標題折疊箭頭改用一致的圖示、按首行置中並擴大點擊範圍。另修正編寫區縮放時的換行順序，避免閱讀留白更新後仍沿用舊的本文寬度而產生水平捲軸。

D-r2 的程式級證據為 4 項外觀設定／首次顯示測試、8 項視窗材質契約、7 項主題、4 項封裝及 16 項編輯測試。合成畫面的 2000／960／720 寬度與 1440 雙欄確認置中、更多工具與折疊往返；另有獨立的設定保存、重開、還原與取消檢查。這些 offscreen／替身呼叫只能證明設定、時序與版面；真實 Windows 首次 Mica 合成，以及清晰透明的實際桌面效果仍待原生試用確認。

### D-r3 文件操作與屬性整理

依使用者要求，屬性的名稱／值排列及左側型別圖示參照 Obsidian 官方設計；不再使用三欄表格、大型多行輸入框及常駐操作說明。清單與標籤可逐項加入、編輯、移除；未知複合值預設收合為原文。取消不寫入，套用仍為一筆可復原交易。

大綱改成編輯區內有留白與細邊界的卡片，依標題層級縮排及折疊，長內容可捲動。搜尋縮成工作列上方的局部控制列；工作列下拉改為小型實心箭頭。閱讀字型、字級、行寬與行距集中在同一個面板，不需穿過多層子選單。

正文頂端為可直接修改的檔案名。按 Enter 提交更名，Esc 取消；分頁、側欄及麵包屑同步，沿用既有引用協調與名稱衝突保護。新文件保持空白位元組，不插入標題或「開始撰寫」提示。`Ctrl+滾輪`、`Ctrl +/-` 縮放目前文件視圖，`Ctrl+0` 還原；不改介面字級、文件內容或其他分割視圖。原文與閱讀模式的檔名會跟隨正文行寬與縮放對齊。

本輪 82 項相關測試通過，涵蓋 Markdown、檔名操作、外觀、設定預覽及封裝。7 項新增 Qt 操作檢查包含更名／取消／衝突、空檔保持、層級跳轉、搜尋、三模式縮放、屬性標籤與型別操作、過期草稿拒絕和一次 Undo。最後的閱讀對齊修正另以實際 DOM 邊距和 Qt 標題位置複驗。1440／960 合成截圖及限定獨立 UI 檢視涵蓋屬性草稿、錯誤定位、窄欄卡片與 100%／120% 縮放；皆為 offscreen 證據，原生 IME、DPI、桌面合成與使用者接受仍待驗。

設計參考：[Obsidian 屬性](https://obsidian.md/help/properties)、[Obsidian 大綱](https://obsidian.md/help/plugins/outline)。參照其操作與資訊結構，未改成 Vault 共用型別或擴充本輪資料格式契約。

### D-r4 大綱密度與搜尋標示（歷史，窄欄配置由 D-r5 取代）

大綱卡片由 200 增至 232 邏輯像素，保留既有字體，導覽文字使用較小且跟隨介面設定的字級。主要章節以字重與段間留白區分；每層縮排 12 像素，長標題最多兩行並保留完整工具提示，列高與卡片高度依內容計算。標題折疊、導覽及原有段落搬移保持。

寬畫面把卡片放在正文左側留白，不改變正文原本的置中位置。中等寬度保留一欄；視窗或分割頁太窄時，改由右上角大綱按鈕開啟浮層，避免持續壓縮正文。浮層可按 Esc、點外側或選擇標題關閉，Esc 僅作用於目前文件。

`Ctrl+F` 的全部命中改為黃底深字，目前命中使用較亮黃色。編寫／原文／基本閱讀使用視圖標示，完整內容閱讀使用 CSS Highlight ranges；不改寫原文、閱讀 DOM、既有選取或 Undo。清除查詢與關閉搜尋會移除標示。

35 項相關 Qt／Markdown 測試通過，涵蓋 H1～H6、長中文與 emoji 標題、收合後高度、正文留白、窄欄與分割頁、跨頁 Esc、UTF-16 搜尋、跨行內格式搜尋、大小寫、取代及復原。960／1280／1440／2560 合成畫面核對了側欄開關、100%／200% 文件縮放與黃色命中；為 offscreen 證據，不替代原生 Windows 操作驗收。

### D-r5 大綱保留欄位

依使用者提供的 Google 文件畫面，大綱開啟時保留自己的左側欄位，正文使用右側剩餘空間並重新換行。窄視窗與分割頁沿用相同規則，不再以浮層遮住正文，也不因點擊正文、選擇章節或按 Esc 自動收起。使用者可用卡片關閉鈕或文件右上角大綱按鈕收合，正文隨即取回空間。

寬畫面仍優先使用正文左側的既有留白，維持正文置中。卡片寬度、六層縮排、兩行長標題與黃色搜尋沿用 D-r4；文件縮放不放大大綱文字。先前建議的頂部收合面板未實作，已由本配置取代。

本次大綱／搜尋 3 項 Qt 檢查通過，涵蓋保留欄位、收合恢復空間、分割頁、跳轉保持及搜尋不改原文。960／1280／1440／2560 的合成畫面核對側欄開關、六層長標題與 100%／200% 縮放；仍為 offscreen 證據，原生 Windows 與使用者接受待驗。

## 本批驗證

使用合成文件驗證 Wiki／Markdown／別名、標題與區塊、同名、更新與循環、YAML 基本型別及未知值保持。Qt 操作驗證 dirty 同檔雙視圖、搬移與另存、故障回復、外改拒絕、保存重開及 Undo／Redo。實際閱讀頁面點擊、來源更新、屬性核取方塊套用與復原在 1440／960 寬度通過。

獨立資料複驗修正並重驗了回復檔案識別、完成紀錄失敗造成錯誤 Redo、跳脫／巢狀連結文字漏抓三個反例。嵌入預算及路徑再驗證有獨立來源審查與純函式回歸；本批新增的 junction 執行複驗未完成，不能冒稱通過。原生 IME／剪貼簿／拖曳、完整語法相容、所有媒體編碼及使用者接受仍不在這份證據內。

語法參考：[連結](https://obsidian.md/help/links)、[嵌入](https://obsidian.md/help/embeds)、[屬性](https://obsidian.md/help/properties)。
