# 工作資源與保存組合

適用 0.8.10 Pre-alpha2 工作資源分支。從 **探索 → 工作資源** 進入。「加入檔案」可引用本機資料夾或匯入對話封存。上方可搜尋名稱、來源、內文與日期，並依全部檔案、文件、對話或已存組合篩選同一份清單；排序與重新整理使用圖示。搜尋命中同一段對話的多則訊息時只列一筆，雙擊後定位到命中的分支。

游標滑過項目時才顯示勾選框，已選項目保留標記。勾選跨搜尋與分頁保留，按「保存組合」輸入名稱即可保存。清單支援標準多選與空白鍵切換勾選。沒有「本次資料包」中介頁、已保存組合的大型下拉選單、「只看已選」或「勾選本頁」按鈕。

雙擊項目在獨立視窗檢視內容，支援全文搜尋、前後命中、Esc 關閉與長文分段顯示。在文件中選取文字，再按「勾選這段文字」可只收錄該段；可收錄多段，重疊範圍會合併。對話可選分支，收錄該分支及共同歷史；直接勾選清單項目時採用該保存版本的目前分支。技術版本、缺件與範圍資訊收在「詳細資料」。主清單不顯示全文。

「已存組合」沿用同一份可搜尋、排序、分頁的清單，開啟一組後列出其中項目。再雙擊可讀保存時的內容，按「核對來源」區分版本一致、改名、變更或不可用。重新指定資料夾與移出清單均保留已保存的組合。此版本保存內容在本機；尚未接上對真實 AI 的傳送或執行。

右上方更多圖示開啟來源管理，可依名稱／路徑搜尋來源、重新掃描、重新指定位置或移出清單。項目右鍵與閱讀視窗的「更多」保留原文唯讀分頁、封存原件匯出、Markdown 複製到工作區及副本編輯；副本使用既有 Markdown 編輯器與 Undo。

## 格式與容量

- 文件索引辨識 Markdown、純文字、RST、CSV、JSON／JSONL、YAML、TOML、LOG。文字須為 UTF-8，可帶 BOM。單檔上限 8 MiB，每一來源最多掃描十萬項，文字總量 512 MiB。畫面分頁列出 50 筆，大篇原文可按段預覽。
- ChatGPT ZIP／JSON 與 Chrome 擷取共用既有匯入解析。ChatGPT 一般來源上限 256 MiB，ZIP 展開上限 512 MiB，Chrome 擷取另沿用 16 MiB 限制。PCS 對話採文件結構與修訂紀錄，大小依既有文件格式。未識別格式（包含未支援的 Codex 紀錄）可明選封存原件，解析限制顯示於清單。
- 附件只記所選訊息中可辨識的參照與缺件，二進位內容留在原封存。分支含選定訊息、必要的共同祖先與來源識別。未解讀內容留在原件。擷取檔的節點順序只涵蓋當時可見訊息。
- 每包 1～512 個選取範圍，選取內容與正式清單合計上限 64 MiB。超限需縮小選區或分包。模型的上下文容量在後續執行階段才核對。

## 保存、資料邊界與程式接點

`work_resources/source_io.py` 以本機 Windows 目錄與檔案 handle 讀取明選來源，核對目錄身分、實際檔案類型、重解析點與硬連結。唯讀來源不需建立 guard。拒絕整顆磁碟、UNC、隱藏路徑與程式的資料目錄。單一來源索引由 `folder_index.py` 背景分批暫存，取消或被取代的工作不發布舊結果。來源或檔案改變時，以完整 SHA-256 判斷能否接受。

`catalog.py` 在專用資料目錄 `work-resources/` 保存登記與可重建的 SQLite 索引。索引含可搜尋的原文，留在本機的應用資料位置。主庫及其 PERSIST journal 在使用期間固定檔案身分。`originals/` 獨立保存匯入的完整原始 bytes 與收據，重建索引不覆蓋既有版本。文件夾引用本身不複製所有原檔。來源更換由明確重新指定觸發。

`stories.py` 從驗證過的封存投影已知欄位。PCS 重生回覆依各次回覆已保存的上下文定位。資料包契約為 `pcs.work-resource-bundle.v1`，與第一階段合成 MCP 分開。每筆選取記來源 ID、版本 digest、文件 byte 範圍或對話及分支識別、排除量和缺項。內容與 manifest 另存於 `bundles/<id>/`，採既有驗證後才寫完成收據的流程。重開以該目錄的清單、大小與 digest 驗證保存內容，再按需比對來源。資料包只在本機使用。

`page.py` 負責單一清單、勾選、分類與保存命令；`list_view.py` 處理懸停勾選、滑鼠／鍵盤操作與共用主題色；`reader.py` 處理離線閱讀、搜尋與選取；`actions.py` 保留來源維護、原件與副本操作。沿用工作區的背景工作與生命週期；搜尋回覆帶入請求序號，過期回覆不更改目前頁面，已關閉工作區不接受回覆。

`Catalog.browse()` 在 SQL 先篩選再分頁，一份對話僅一列；以同次查詢取得匹配總數，取消事件可中止查詢。頁面不載入來源全文。勾選只持有來源版本與選區等中繼資料，保存時由 `bundles.materialize()` 批次核對並讀取，同份文件的多段範圍不重複讀檔，同封存的多段對話共用一次解析。保存仍沿用原有版本再核對與完成收據，檔案格式及保護契約沒有變更。

保存組合的清單只載入 manifest 摘要並快取；搜尋、排序與翻頁不重讀全部內容。開啟指定組合後才驗證及載入該組內容。原文分頁使用已核對的 bytes，副本回到 Markdown 文件樹、分頁、寫入及 Undo。來源、固定組合和 MCP 合成工具各有獨立邊界。
