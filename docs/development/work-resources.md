# 工作資源與本機資料包

適用 0.8.10 Pre-alpha2 工作資源分支。從 **探索 → 工作資源** 進入。選「加入來源」引用本機資料夾或匯入對話封存。搜尋可比對檔名、來源、內文以及日期（YYYY-MM-DD）。點一筆原訊息會定位到包含它的分支。原件的分頁供閱讀，Markdown 的「複製到工作區」會在目前內容資料夾建立獨立副本，並開啟既有編輯器。

在預覽中選取文字，再按「加入資料包」即可只收錄該段，沒有選區時收錄全文。對話收錄所選分支與其共同歷史。在「本次資料包」可逐項看原文、範圍、版本與缺項。保存後到「已保存」查回，按「核對目前來源」能分辨版本一致、改名、變更或來源不可用。重新指定資料夾與移出清單均保留已保存的資料包。封存來源的操作選單可匯出完整原件。

## 格式與容量

- 文件索引辨識 Markdown、純文字、RST、CSV、JSON／JSONL、YAML、TOML、LOG。文字須為 UTF-8，可帶 BOM。單檔上限 8 MiB，每一來源最多掃描十萬項，文字總量 512 MiB。畫面分頁列出 50 筆，大篇原文可按段預覽。
- ChatGPT ZIP／JSON 與 Chrome 擷取共用既有匯入解析。ChatGPT 一般來源上限 256 MiB，ZIP 展開上限 512 MiB，Chrome 擷取另沿用 16 MiB 限制。PCS 對話採文件結構與修訂紀錄，大小依既有文件格式。未識別格式（包含未支援的 Codex 紀錄）可明選封存原件，解析限制顯示於清單。
- 附件只記所選訊息中可辨識的參照與缺件，二進位內容留在原封存。分支含選定訊息、必要的共同祖先與來源識別。未解讀內容留在原件。擷取檔的節點順序只涵蓋當時可見訊息。
- 每包 1～512 個選取範圍，選取內容與正式清單合計上限 64 MiB。超限需縮小選區或分包。模型的上下文容量在後續執行階段才核對。

## 保存、資料邊界與程式接點

`work_resources/source_io.py` 以本機 Windows 目錄與檔案 handle 讀取明選來源，核對目錄身分、實際檔案類型、重解析點與硬連結。唯讀來源不需建立 guard。拒絕整顆磁碟、UNC、隱藏路徑與程式的資料目錄。單一來源索引由 `folder_index.py` 背景分批暫存，取消或被取代的工作不發布舊結果。來源或檔案改變時，以完整 SHA-256 判斷能否接受。

`catalog.py` 在專用資料目錄 `work-resources/` 保存登記與可重建的 SQLite 索引。索引含可搜尋的原文，留在本機的應用資料位置。主庫及其 PERSIST journal 在使用期間固定檔案身分。`originals/` 獨立保存匯入的完整原始 bytes 與收據，重建索引不覆蓋既有版本。文件夾引用本身不複製所有原檔。來源更換由明確重新指定觸發。

`stories.py` 從驗證過的封存投影已知欄位。PCS 重生回覆依各次回覆已保存的上下文定位。資料包契約為 `pcs.work-resource-bundle.v1`，與第一階段合成 MCP 分開。每筆選取記來源 ID、版本 digest、文件 byte 範圍或對話及分支識別、排除量和缺項。內容與 manifest 另存於 `bundles/<id>/`，採既有驗證後才寫完成收據的流程。重開以該目錄的清單、大小與 digest 驗證保存內容，再按需比對來源。資料包只在本機使用。

`page.py` 使用工作區的探索分頁及背景工作生命週期，來源與搜尋回覆帶入該次選擇。原文分頁使用已核對的 bytes，管理副本回到 Markdown 文件樹、分頁、寫入及 Undo。來源、固定資料包和 MCP 合成工具各有獨立邊界。
