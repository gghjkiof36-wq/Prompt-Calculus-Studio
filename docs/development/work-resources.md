# 工作資源：資料夾、閱讀與對話轉 Markdown

適用 0.8.10 Pre-alpha2。由「探索 → 工作資源」進入。本文說明檔案模式：閱讀本機文件、整理工作區資料夾，以及把歷史對話轉成普通 Markdown 文件。同頁另有精簡的 Skill／Agent 模式，使用方式與限制見[本地 Skill 與 Agent](local-agents.md)。檔案閱讀和對話匯入不會啟動模型工作。

## 操作

- 「加入檔案」可加入外部資料夾或對話封存。資料夾直接對應磁碟目錄；進入後顯示目前位置並可返回上層。搜尋目前資料夾時包含子資料夾，結果的來源欄顯示相對位置。
- 單一篩選選單提供全部檔案、文件、對話、規則與定義。清單最大內容寬度為 920px，置中排列，沿用管理頁的間距；窄窗優先保留名稱。沒有獨立的類型欄。
- 對話列的勾選框在懸停、鍵盤定位或已勾選時顯示。勾選跨搜尋、翻頁及資料夾導覽保留。按「輸出 Markdown」選目的資料夾，每份對話各自輸出；結果逐份列出成功、失敗及未處理。單份成功會開啟文件，多份不大量開分頁。
- 也可直接從首頁的開啟檔案選擇 ZIP／JSON／Codex JSONL，預覽並勾選對話後輸出。不必先加入工作資源或建立組合。
- 工作區內一般 MD 直接回到既有首頁分頁閱讀，同一份文件再次開啟會回到既有分頁。外部 MD 在獨立視窗以既有 Markdown 閱讀器顯示，必要時選「在首頁開啟副本」。右鍵可隨時選獨立視窗閱讀。
- 工作區內可新增資料夾、改名及移動文件／子資料夾，也可單選或多選後直接拖進清單中的資料夾；有效目的地會高光提示。同名檔案另取可用名稱，取消拖動不搬動文件。沿用首頁的檔案交易、同一根資料夾移動及連結修復；多選逐項完成，若失敗會停止並列明完成及未移動的數量。外部來源的原件只有讀取／解除登記，不提供破壞性整理。來源管理在右上角更多選單。
- AGENTS.md／CLAUDE.md、SKILL.md、agent.md／agent.toml／agent.yaml／agent.yml 及 agents 目錄下的定義依用途標示。其管理副本放在應用資料內，沿用 Markdown 編輯器，不自動加入普通首頁文件，也不啟用任何指令、腳本或平台設定。名稱辨識僅供分類，不是完整 Skill／Agent 執行格式支援。
- 「已存組合」入口、保存組合及選區組包操作已移除。既有 bundles 目錄、收據、原件及底層讀取契約保留，沒有清理或遷移使用者歷史資料。

## 對話格式與保留範圍

### Codex rollout JSONL

`codex_archive.py` 接受含唯一 session_meta 的本機 JSONL。固定實測樣本為 Codex Desktop 0.165.0-alpha.1.2，包含 event_msg/item_completed 的 UserMessage／AgentMessage。以可見事件為該角色的正文投影，不再混入同角色的 response_item 模型輸入／輸出；在選定投影內按訊息 ID 去重，重複 ID 內容衝突則停止。不同 ID 即使文字相同仍保留。這不是用文字相似度合併訊息，也不是任意版本 Codex 封存的完整支援承諾。

沒有可見事件的角色可使用 response_item/message 中已識別的使用者／助理訊息；已標記的環境注入、analysis、system／developer 不納入。工具事件、推理、compacted、其他未知紀錄保留原 JSONL，正文附轉換範圍。若舊來源未標示環境注入，無法僅憑文字可靠還原其用途，須核對原件。缺失時間不補造；可取得的時間顯示為 UTC。正文保留訊息順序、中文、程式碼及清單。

完整來源另存於輸出資料夾的原始封存.jsonl，並保留已解讀投影、來源 SHA-256、解析統計、圖片雜湊及完成收據。原始 Codex 檔、索引與封存狀態均不改動。不掃描全體 .codex 歷史。

Codex 圖片只接受來源內嵌的有界 PNG，或所選封存同目錄內的相對 PNG/JPEG/WebP/GIF。重解析點及越界路徑拒絕；絕對路徑、遠端網址和未提供內容的附件明示未轉出。內嵌 PNG 沿用 2 MiB／16M 像素驗證；相對圖片每份上限 2 MiB，合計 128 張／16 MiB，超額項目標明未轉出。成功附件以相對 assets/ 引用，可離線閱讀。從保留版本輸出時只在來源目錄身分仍吻合時讀取相對附件，並記錄這次實際取得內容的雜湊。

### 其他來源

ChatGPT ZIP／JSON 與既有瀏覽器擷取格式沿用原解析與附件保留機制；PCS .pcs-chat 依各次回覆保存的上下文建立分支，不把草稿或系統設定當成問答。一般來源上限 256 MiB、單次匯入輸出 512 MiB、單篇 MD 8 MiB。多分支／長文沿用分卷，主文件提供相對連結；單一分卷直接形成可讀主文件，不再同時顯示一份重複分支 MD。

## 檔案、索引與完成時點

`conversation_import.py` 的 readable 模式先在目的目錄 .pcs/conversation-imports/ 建立本次獨占暫存，全部檔案與完成收據落盤後，才用既有 exclusive rename 發布為可見資料夾。重名使用新名字，從不覆寫原有文件。取消／失敗保留可識別的內部未完成輸出，不出現在首頁文件樹。舊匯入模式的重複匯入辨識及擷取收據接點保持原行為。

`work_resources/exports.py` 每次批次共用同一封存的解析，逐份發布、核對及登記普通工作區副本；已完成檔案即使隨後來源登記失敗也會如實列為已保存，另列登記錯誤。取消保留先前成功項目。首頁匯入及資源頁輸出在保存成功後才刷新文件樹；目的目錄在現有首頁根外時，以既有加入資料夾方式顯示。

`catalog.py`／`folder_index.py` 保留來源、固定版本與可重建的 SQLite 索引。`originals/` 留存明選封存原件，索引包含本機可搜尋文字。單一來源最多十萬項、單檔文字 8 MiB、總文字 512 MiB；搜尋先 SQL 篩選再分頁，每頁 50 筆。一份對話只列一筆。`navigation.py` 只導覽已登記根；首次進入／搜尋時按需建立索引，明確重新整理才重掃，不增加輪詢。

`workspace_file_operations.py` 在既有檔案移動交易完成後，更新已登記管理副本的位置與索引；主交易失敗不變更來源。更新索引失敗時保留已完成的文件移動並明示待核對。首頁仍是檔案與編輯緩衝的唯一擁有者，資源清單不建立另一份文件資料庫。

`page.py`／`list_view.py` 處理置中清單、勾選與導覽；`actions.py` 與 `file_drag.py` 呼叫共用檔案操作。拖放只接受同清單當次選取的來源身分，開始拖動時暫停相關保存並捕捉來源，放下前核對；移動期間不在各項之間重建清單，避免重複掃描與失去選取。`markdown_preview.py` 將既有 MarkdownPage／MarkdownSurface 放入獨立視窗。外部原件不保存，規則管理副本的編輯只能寫回副本。`reader.py` 保留對話全文搜尋／分支檢視，不再建立選區資料包。來源內容不作指令執行。

檔案背景工作沿用現有 Jobs／ImportJob，搜尋結果按請求序號採用，已關閉的工作區不接受 UI 回寫。這些檔案操作不新增 MCP 執行、外部模型通訊、登入或全域設定變更；本地角色的唯讀迴圈從既有聊天送出，沿共用 LocalAIService 執行。
