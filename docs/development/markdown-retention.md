# Beta3：演示、對話整理與可攜包

本文件描述 0.8.9 Beta3 的本機實作增量，承接 Beta2 的 MarkdownBuffer、對話匯入與目錄保護。操作見[使用指南](../guide/markdown-retention.md)。不引入模型服務、登入憑證或本機資料庫遷移。

## 接點與責任

| 模組 | 責任 |
| --- | --- |
| `retained_files.py` | 有界穩定讀取、來源／目標身份、獨占新目錄、檔案清單與最後完成回執 |
| `retained_dialog.py` | 共用非模態視窗、ImportJob 背景工作、取消、來源視圖快照與生命週期 |
| `markdown_demos.py`、`markdown_demo_dialog.py` | 演示原件／預覽／依賴的不可變保存、缺項檢查、修訂及單筆正文交易 |
| `conversation_review.py`、`conversation_review_dialog.py` | 原文查回、分支分段、人工回覆引用驗證、候選修訂、釘選與接續輸出 |
| `conversation_resources.py` | 從匯入回執或擷取來源中解析所選訊息附件；驗證並保留內容與追溯 |
| `markdown_portable.py`、`markdown_portable_dialog.py` | 凍結目前文件與顯式範圍、追蹤相對資產、資料夾／ZIP 寫入驗證及獨立重開 |
| `markdown_surface.py`、`markdown_toolbar.py`、`markdown_relations.py` | 命令／選單入口、明確連結點擊；不增加常駐側欄 |
| `workspace_shell.py` | 關閉時通知本批視窗取消，拒收已關閉 owner 的回呼 |

## 內容與非同步歸屬

演示先固定選取 bytes、檢查依賴，再完整保存，最後才用既有 `SourceEdit` 一次插入／替換 Markdown。引用是普通相對連結，加上唯一演示區塊標記。Undo／Redo 僅處理正文，附件和歷史修訂不隨之刪除。

視窗保留文件路徑、root 身份、MarkdownBuffer snapshot 與選取位置。真正修改正文前再次檢查相同 snapshot／位置、視圖仍可見、非閱讀與非組字。背景完成後若狀態已變，拒絕插入，已完成檔案仍保留。匯出採用開啟視窗時的正文快照；預覽完成的 bytes 固定，之後寫出同一份內容。改變範圍需重新預覽。

新視窗沿用既有 `ImportJob`。關閉／取消設置事件，等待安全檢查點；不以銷毀 UI 當作工作已停止。單次 JSON 解析、雜湊與寫入仍可能持續到下一檢查點。未改既有文件保存、恢復及共用視圖歷史契約。

## 身份、修訂與資料界線

演示的 `演示.json` 保存格式版本、穩定物件 ID、修訂、原檔／預覽角色、相對路徑、大小／SHA256、來源及缺項。新修訂 deep-copy 原關係資料，保留未知欄位與上版修訂。原件與預覽用同一路徑時仍檢查兩次讀取內容一致，不接受混合修訂。

對話沿用 `conversation_archive` 的有效來源資料。原訊息 ID、parent 路徑與來源 digest 決定查回及候選身份，檔名與顯示標題不是身份。全分支搜尋以節點去重，保留分支成員；所選分支擷取只保存必要祖先與節點，刪除子圖外的 children 連結。未知節點欄位保留；未知頂層欄位可能藏其他分支，因此範圍擷取只保留已知身份／標題／時間，並明確標示 `pcs_extraction`。

沒有來源 ID 時，首次解析得到的穩定 key 會寫入擷取資料。來源摘要與有限修訂鏈支持重複保存後仍正確追溯；不能只比當下重排 JSON 的 bytes 而誤認更新。候選內的 request 包含對話、分支、來源 digest、段次、用途、長度與釘選。模型回覆只能引用該段來源，所有項目先標為未核對。候選標記 `automatic=false`，模型未驗證，不能作自動摘要驗收證據。

接續文字包括分類、人工核對狀態、完整釘選與引用原文，接收方不需要存取來源機器才能閱讀。三個輸出出口共用上限／釘選檢查。保存同時保留實際手改 Markdown、其 hash、候選、所選原始對話及可取得附件；重算另開候選，不覆蓋人工版本。未提供自動差異合併或多分支共同摘要快取。

## 檔案與可攜寫入

`read_local` 拒絕連結／重解析點與非一般檔，限制 bytes，核對開啟前後 handle 及路徑身份。Windows 沿用現有目錄 pin／受保護 reader。多檔準備最後重新核對來源 hash；目標在建立附件或整理稿父目錄前核對被選取的目錄身份。讀 ZIP 前即捕獲目標身份，不能解析後才信任同一路徑。

保存以獨占新目錄為邊界，先寫 `保存開始.json`，檔案 flush／fsync，讀回驗證後最後寫 `保存完成.json`。不覆寫或遞迴刪除既有結果。ZIP 先寫本次 `.incomplete.zip`，重新驗證清單與全部內容後發布新檔名。失敗／取消保留可辨識的未完成輸出。

可攜範圍是目前正文、可定位附件、嵌入的普通筆記，以及顯式選定對話子圖。來源原始 JSON、跨對話文件和一般關聯筆記不因一條連結就擴大範圍。正文中的訊息錨點跨目錄／改名仍用於比對允許分支。清單排除設定、憑證及診斷路徑；不是任意內容的機密掃描器。

驗證 ZIP 路徑、大小寫衝突、檔案／資料夾衝突、連結、加密、版本、實際 bytes／hash 及清單覆蓋。開包另建獨立副本，不需要舊 DB。普通 MD 閱讀與 PCS 額外追溯的驗證程度分開記錄。
