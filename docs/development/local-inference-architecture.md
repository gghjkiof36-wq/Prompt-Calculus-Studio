### 基礎版受驗來源與結果（歷史證據）

契約測試基準為 `f2d0ad9a432a73e4d0b31b6f9bbcb7b7bdcb2e17`。真模型及原探索頁驗證使用該基準加 `runtime.py` 的 `--reasoning-format none` 修改；固定檔案摘要及最後交付提交由任務回執記錄。此參數讓 R1 的思考文字保留在目前支援的 `content` 串流，避免預設 `auto` 將它拆到尚未接受的 `reasoning_content`。原文完整保存；後續新增的顯示層將前導 `<think>` 區塊獨立呈現，不改這份傳輸與保存契約。

- **42 項有界測試通過**：文件契約 18、假服務 owner 10、引擎／設定與串流契約 14。首次受限執行的 Windows 原子改名失敗保留原始紀錄；相同來源在具備所需本機權限後通過，沒有為此修改產品碼。
- **7 項離屏實頁檢查通過**：探索空態、真 GGUF 登記但不載入、1440×900／900×760 布局、按鈕建立 `.pcs-chat` 並讀回、從對話返回同一探索頁與共用服務、正常關閉。窄窗詳情動作可捲動到達；本輪沒有建立推理 worker。
- **真 `LocalAIService`＋`ChatDocument` smoke 通過**：固定模型載入、兩輪串流與上下文記憶、保存重開一致、停止後保留部分文字並落盤、卸載及自有程序退出。使用隔離資料和無可見 UI 的 Qt 驅動，不能視為原生對話介面的操作驗收。

真模型測試採上下文 2048、回覆上限 384（停止案例 768）、temperature 0.2、top-p 0.9、seed 42、GPU layers 8；只將自有引擎限制於 4 個邏輯 CPU 與低於正常優先序。單次記錄載入 2.782 秒、兩輪各 58.781／41.110 秒；這是保守資源配置下的一次功能檢查，不是冷啟動、首字速度、完整 GPU 加速或效能基準。卸載經自有程序終止完成，回執記退出碼 1，沒有把它記成一般正常退出碼 0。原始回執與畫面連結由任務 STATUS 維護。

離屏檢查首次遇到字庫未自動載入，第二次僅於測試程序加入既有 Windows 字型後取得可讀 PNG；原始圖與 Qt 訊息保留。另有既有 `CanvasNotice` 負尺寸警告，未影響本輪接點。原生 DPI／IME、長文互動、強制當機恢復、OOM、完整效能量測及正式包驗收仍未完成。

### 探索入口與本機介面檢視

依使用者補充，模型匯入與管理集中於既有「探索」頁的「本地模型」入口，與 ComfyUI 模型資產分開。探索左欄固定列出 ComfyUI、CivitAI、本地模型與下載紀錄，取代中央入口卡片。對話頁「管理模型」導向本地模型頁；模型、生成設定及明確綁定來源文件的對話指示集中於此。頁面延後至使用者開啟時建立；`local_ai.service.for_workspace` 確保先開模型頁或先開對話都使用同一個 workspace service、registry 與引擎狀態。檢視頁面、選取清單及開新對話都不自動載入模型。

`tools/launch_local_chat_preview.py` 提供本機 BAT 的預覽啟動接點：使用交付目錄下獨立的 files／data／logs，僅在 files／data 皆空時建立空白對話，沿既有工作區入口開啟這份來源。最初靜態回執不再代表本任務尚未允許運行。原生預覽已啟動過，R1 與固定引擎也已排他登記至原先不存在的 preview registry；未覆寫文件或既有模型登記。使用者重新開啟後可讀到登記；選擇模型並送出訊息時，服務會自動準備模型。它依賴目前電腦的 Python 與工作樹，不是 EXE 或可攜安裝包；實際路徑與啟動方式以預覽目錄的使用說明為準。

### 對話頁骨架

空白頁與有訊息頁共用一份輸入框、可搜尋的模型選單及送出／停止控制。空白頁置中，有訊息後輸入區固定底部；訊息與輸入框共用設定頁的 `READING_CONTENT_WIDTH`（740 logical px），窄窗跟隨可用空間。對話捲軸位於整頁右緣，與輸入框內部長文捲軸分開。使用者文字靠右成自然寬度氣泡，模型回覆左對齊排正文；重試的舊回覆完整保留並可展開。文件仍使用 `.pcs-chat` envelope 與原有 owner；附件及編輯紀錄透過 required feature 擴充，準備模型納入同一份請求的生命週期。

模型選單與圓形送出／停止按鈕相鄰於右下，停止使用實心方塊；匯出與編輯紀錄收在頁面右上「⋯」，重試位於可重試回覆旁。輸入框不顯示快捷鍵說明、設定或手動載入／卸載。可搜尋的模型選單保留選用標記及「管理模型」入口，選模型只保存選擇，不啟動引擎。輸入法組字時暫時隱藏 placeholder，採與 Markdown 編輯器相同的無白底組字格式，保留原生候選和 Enter 確認保護。

送出及重試先由 `ChatDocument` 保存固定參數、模型、訊息與 owner，`LocalAIService.submit` 再以同一個 worker 命令準備模型並生成。準備期間已占用唯一生成槽，沒有先 ready 再提交的空窗；重複送出與其它文件搶用被拒絕。切換模型、上下文或 GPU 設定只在下次送出時重新準備；停止、另存、關閉沿同一請求撤銷接受權，載入錯誤與取消不觸發自動重試。保留底層 load/unload API 供生命週期及既有契約使用，但不是聊天的使用者步驟。

模型的前導 `<think>…</think>` 由顯示層分為可收合的思考區與正式回答。接收時預設展開，使用者可手動收合；箭頭位於名稱右側，高度過渡沿共用動畫並尊重減少動態設定。進入終態時自動收合一次，後續一般刷新不覆蓋使用者的展開選擇。生成時不顯示回覆底部動作或「接收中」，結束才提供複製、分支等適用操作。原始回覆仍完整保存在 `.pcs-chat`；此解析不猜測正文或程式碼中的字面標記，也不宣稱已接入獨立 `reasoning_content` 欄位。

本地模型庫、模型設定、共用引擎設定與來源對話指示使用與其他設定頁相同的置中內容寬度。清單提供名稱、修改時間與檔案大小排序；模型列保持緊湊，動作收在「⋯」，齒輪進入該模型的設定子頁。資料夾操作只掃描及登記既有 GGUF 引用，保留手動登記及舊模型原檔，不將更改目錄解讀為搬移或刪除。模型資料夾掃描與推論分開執行，不占用生成槽，也不啟動模型。

本輪新增的模型預設以模型 UUID 分開保存上下文、回覆上限、溫度、top-p、seed、GPU layers 及預設提示詞；引擎位置與閒置時間仍屬共用設定。原有共用值保留作未設定模型的預設，重置只影響指定模型。對話若已有非空提示詞，優先於模型預設；實際採用的參數及提示詞仍固定在每次回覆記錄中，既有回覆與已接受請求不隨設定變更改寫。模型設定保存須核對原模型 ID 與載入表單時的版本，拒絕失效或過期表單。

工具審查偏好獨立於模型預設與推論參數，舊資料預設為每次詢問。四種方式為關閉、每次詢問、自動審查、全部允許；自動審查使用 host 明確登記的安全本地讀取規則，其餘需詢問，不宣稱已有額外審查模型。政策拒絕未登記能力、影響不符與範圍驗證失敗的動作；未來執行器仍須在執行與接受結果時核對 owner、路徑及資料契約，政策允許不等於取得可寫 owner。目前尚未接入模型工具呼叫，選單只保存偏好並提供後續執行邊界；不從普通回覆解析命令、不新增 Shell 或 API。一般文字送出不經工具審查。

每模型另保存思考模式（依模型／開啟／關閉）與思考上限（依模型／不限／自訂）。`local_ai.reasoning` 保持無 Qt，與六個既有可攜參數分開；每次請求凍結獨立 reasoning 快照，含此欄位的現行及歷史回覆須宣告 `pcs.chat-reasoning.v1`，讓不支援的舊 reader 明確拒絕。無此欄位的舊文件仍可讀，不回填或改寫舊回覆。

思考切換限於已核對的 Qwen3.5 模板與 llama.cpp b11900；執行時由 `/props` 核對 build 與模板 SHA-256，再以 `/apply-template` 比較開關結果。該模板預設思考上限為 `min(512, max_tokens-1)`，明確「不限」保留，關閉思考則不附上限。其他模型的預設沿引擎行為；明確要求未經確認的控制會給出錯誤，不默默忽略。自訂上限須小於回覆上限；未知模板另須證明可解析起訖思考標記。上限快照代表請求策略，並非實測思考 token 數或答案品質保證。

停止、中斷、失敗或達長度上限的回覆若仍處於未閉合的前導思考區，且未明確關閉思考，下一輪不將該片段當 assistant 答案送回；保存原文、歷史及引用不變。正常完成的回覆、明確關閉思考的回覆，以及正文或程式碼中的字面標記均保留在後續上下文。

舊程序若已載入不含新鍵的設定模組，新設定頁沿可用服務介面顯示及保存原有參數；不自動熱換既有服務。新的思考控制在重新開啟後生效。自動硬體調整、batch 與 Flash Attention 仍屬後續；API 依使用者要求暫緩。

### 回覆顯示與分支

純文字維持原生 Qt 顯示；程式碼、表格、數學式及圖片才延後建立封閉的 WebEngine 顯示頁。公式沿用 Markdown 的語法與隨附 KaTeX，支援上下標與科學記號；程式碼有獨立複製動作。顯示投影不改寫保存的原文，也不執行回覆中的 HTML／JavaScript。遠端或任意本機圖片不自動讀取；目前可顯示有界的 PNG／JPEG／WebP data URI，SVG 不接受，Mermaid 暫以原碼呈現。

WebEngine 顯示頁共用一份無持久化 profile，僅開放精確的隨附顯示資產與已驗證圖片。DOM 按區塊更新，既有區塊和文字選取保持穩定；選取期間暫緩內容投影，解除後追上來源。離開可視區且沒有選取的顯示頁可釋放，保留內容與已量得高度，重訪再建。模型生成與文件 owner 均不依賴這些顯示頁存活。

訊息旁可建立獨立 `.pcs-chat` 分支，複製至所選訊息／回覆的前綴並重配文件、訊息、回覆與請求身分。來源仍在生成時，分支保存當下文字並標為中斷；來源繼續接收，晚到回覆不能寫入分支。來源未送出的草稿不跟著複製。分支建立採排他的新檔名稱、讀回再開啟，不覆寫同名原件；開啟失敗保留已建立檔案的位置。既有回覆的模型及參數快照保留，下次送出仍遵守目前選定模型和其設定。

### 前端與資料成本

成功保存必須完成原有替換、讀回及衝突確認，才在父目錄固定保護內清除**當次**恢復副本；失敗、外部競寫與不確定的替換結果保留副本及錯誤狀態。這不是歷史清理機制，既存 recovery 檔沒有可靠接受標記，不按名稱或雜湊批次移除。文件樹與索引使用 `os.scandir` 並先排除已識別的內部恢復檔，避免對大量副本逐一解析路徑；普通相似名稱文件仍會顯示。

對話頁按可見性及內容長度合併串流投影，計時只更新輸入列文字；完成後耗時留在 owner 記憶體。工作區監測被動觀察重繪與 GUI 延遲，行為詳見 [UI 原則](ui-patterns.md)。這些調整處理前端／檔案成本，不代表模型推論速度或 LM Studio 對比已驗收。

推理在獨立 worker，自有 llama-server 程序承擔模型運算；跨執行緒只傳入固定請求與增量文字。文件每 60 ms 合併一次畫面通知，保存檢查點沿原有 1500 ms 排程；這兩個數字是排程值，不是即時延遲保證。UI 不把每個 token 當成重建整份訊息串的理由。

自動保存由 chat 專用背景工作執行，共用 writer／CAS 契約不變；WorkspaceAutosave 的 chat 分支也走同一入口，避免另一個計時器仍同步保存。每個 owner 同時最多一份不可變快照，完成後以文件 key、owner epoch、路徑與 job token 核對。成功只更新保存基線及 receipt，不覆蓋期間新增的文字；仍有差異才排下一次。改名、移動、另存、關閉與明確保存先等待原工作完成；等待逾時保留頁面與待保存內容，不改換路徑或丟棄寫入結果。

相同 400 輪、14.45 MB 合成文件，原同步自動保存約阻塞 1953 ms；背景版本取快照／派送約 120 ms、最大 Qt 計時器間隔約 120 ms，總落盤約 1664 ms。含圖片的 15.85 MB 案例最大間隔約 179 ms，5 組資料皆保存並讀回一致。這是隔離真 Windows writer 的量測；快照仍在 UI 執行緒，背景 Python 編碼仍有 GIL 成本，不能稱為零停頓。明確 Save／Send 前保存與終態保存仍可等待磁碟；沒有用提前宣稱成功換取表面流暢。

對話首次只建立最近 30 輪的 widget，較早內容按批加入並保留捲動錨點；完整歷史、上下文和原始文件都保留。未變的回合跳過重新呈現。文件投影直接複製現行 payload，分支只複製所需前綴，避免先複製整份舊內容再丟棄。進本地模型或外觀頁不再順帶刷新已開過的 ComfyUI 頁；模型列只有內容或主題變更才更新圖示。

2026-10-27 的相同合成資料、Qt 離屏比較：300 輪初次開頁約 4.80 s 降至 0.81 s，串流刷新中位約 23.61 ms 降至 1.51 ms；加入最後的複製按鈕及捲動修正後，複核為 0.90 s／2.65 ms。24 則格式化回覆的活動顯示頁由 24 降至 2（單一共享 profile）。400 輪、14.4 MB 文件的首則分支約 926 ms 降至 27 ms，末則分支約 1717 ms 降至 899 ms。模型庫 200 筆未變資料刷新中位約 16 ms 降至 0.96 ms。這些是特定 fixture 的前端／資料成本，會受機器負載影響，不是模型 tokens/s，也不代表最終原生介面效能驗收。原始前後收據由任務 STATUS 索引；附件等後續變更另附其來源與驗證。

架構核對採用 [Qt WebEngine lifecycle](https://doc.qt.io/qt-6.11/qwebenginepage.html) 對隱藏頁面的資源管理原則，以及 [Open WebUI 效能說明](https://github.com/open-webui/docs/blob/main/docs/troubleshooting/performance.md) 對串流批次和重複處理成本的討論。PCS 的「按可視區建頁、保留選取、增量通知」是依現有 Qt 結構作出的設計選擇；沒有照搬多使用者 Web server 設定，也沒有為此換框架或加入外部服務。

生成錯誤使用對應回覆內的淡紅底細框與可選取文字，依文字長度決定框寬，保留已收到內容。重試圖示放在回覆下方操作列；未能建立請求的操作錯誤也放在對話區，輸入稿保留。正常停止只顯示一次「生成已停止」，不附空回覆或重複狀態。正常畫面不增加操作教學和實作說明，編輯框只保留文字與取消／送出。紅框的原先選型參考 [Carbon inline notifications](https://www.carbondesignsystem.com/building-blocks/core/components/notification/guidelines) 與 [Fluent message bar](https://fluent2.microsoft.design/components/web/react/core/messagebar/usage)，本輪比例依使用者提供的對話錯誤畫面調整，配色和元件仍沿 PCS 共用 tokens。

使用者原型是本輪視覺基準。2026-10-27 另對照主流產品官方操作文件：[ChatGPT 將模型選擇放入輸入區](https://help.openai.com/en/articles/6825453-chatgpt-release-notes)、[Claude 將模型選單放在送出旁](https://support.claude.com/en/articles/8664678-change-the-model-effort-and-thinking-settings)、[Gemini 在輸入框底部選擇模型](https://support.google.com/gemini/answer/18648722)、[LM Studio 基本對話操作](https://lmstudio.ai/docs/app/basics)。這是上一輪骨架的代表產品對照，並非全市場調查或像素複製；本輪依使用者補充改為送出時自動準備模型，附件另按下節接入，不增加未實作的語音入口。

目前逐段輸出使用同一個 worker 的 Qt queued signals 保序，接受端核對完整不可變 ServiceRequest 與本地 owner。尚未實作跨服務重送或序號去重協定，不能把這個同程序事件通道直接作日後公開 API。`profile_epoch` 是模型 UUID 與可攜參數的 UUIDv5 指紋；不是引擎執行階段身分或模型權重 hash。路徑、臨時憑證不寫入對話文件。

保存沿既有文件 writer 與 CloseRecovery，未另建對話資料庫或增量 journal。停止或失敗後可直接送出下一輪：固定各舊輪最新終態回覆的引用，保留部分文字，完全沒有文字則不捏造 assistant 訊息。這類引用使用 `pcs.chat-revisions.v1` 必要能力標記，舊讀取器不得默默丟棄不認識的語意。最後一輪可以原地重試，只新增回覆嘗試，不重複 user 訊息，也不覆蓋輸入區草稿。

使用者訊息提供原地編輯及重新送出。修改前的整條有效路徑保存為同文件 `revisions` 快照；快照包含原指示及訊息／回覆，不遞迴複製更早的 revisions，也不帶入未送出草稿。同檔最多 100 份紀錄，仍受 32 MiB 總上限約束。前檢核對 owner、模型參數及附件，沿 CAS 保存成功才替換目前路徑。前檢或保存失敗保留原路徑及編輯稿；已保存後才發生的載入／生成失敗則保留新 failed attempt。

訊息下方的「檢視版本」開啟唯讀視窗，依明確編輯路徑與訊息身分列出該訊息的版本，不用文字相似度推定。前後切換與「返回目前版本」只影響預覽；「在新對話中建立分支」複製選定版本當時的完整路徑，沿現有排他建立、讀回及新頁開啟程序，不改來源。複製時跨快照共用同一身分映射，保留版本關係並隔離新文件所有 ID；舊副本若已失去同源身分，不臆測修補。原有恢復方法保留供既有資料路徑使用，版本視窗不以恢復覆寫目前對話。

編輯頁面持有 owner 的排他資格，同文件其他頁不能送出、重試、編輯、恢復或建立分支。發布編輯／恢復前等待原檢查點完成；同步 CAS 期間不另啟保存。編輯輸入期間仍可保存原已接受內容，但不把未送出的編輯文字混入文件。實際修改會阻止關閉及檔案重定位，未改字的編輯框可自動取消並釋放資格；這與助手回覆的獨立文件分支是不同操作。

### 附件與文件互通

輸入區左下的「＋」提供檔案與 PCS 文件；右側為有背景及邊框的審查按鈕。文字貼上使用純文字，圖片可由剪貼簿或本機檔案拖入。圖片附件顯示 64 px 方形縮圖而不顯示檔名，草稿保留移除鈕；文字附件仍為具名項目。點圖顯示完整快照、調暗背景，空白處或 Esc 關閉並返回原焦點，不讀取原始路徑或網路資源。輸入框使用 24 logical px 圓角，文字區隨換行成長至 200 px 後使用內部垂直捲軸，工具列不跟著文字捲動。

`local_ai/attachments.py` 使用獨立、單一工作槽讀檔及轉換圖片，不占推理槽。匯入批次以原文件 key、owner epoch 及 job token 接受；切頁不換接收文件，關閉或另存撤銷舊結果。批次驗證失敗不加入半份附件，原草稿不變。讀入期間仍可輸入文字，接受時重新檢查目前草稿。

剪貼簿圖片在 UI 僅取得獨立的 QImage 共享快照，PNG 壓縮與縮圖交由背景工作；1600 萬像素的交接量測首次約 0.80 ms，不包含 Windows 提供剪貼內容時的解碼。Emoji 原文、複合序列、保存與複製已核對；實際字形依平台字庫，當前 Windows 字庫的部分旗幟呈現為字母，不宣稱所有平台都顯示彩色旗幟。

附件為自包含快照：文字保存 UTF-8 內容；圖片轉成 PNG，原檔不改動。每輪／草稿最多 8 件，單一原檔最多 8 MiB，文字最多 200,000 字元；原圖最多 16 MP，保存圖片縮至不超過 4 MP／2 MiB，附件合計最多 16 MiB，文件仍受原有 32 MiB 上限約束。新增 `pcs.chat-attachments.v1` 必要能力旗標；舊無附件文件保持可讀，不支援此旗標的舊版本應明確拒絕，不悄悄丟附件。

文字附件只加入 user 訊息，不升格為 system 指示；重試、保存重開及分支沿已接受快照，不重新讀取來源。現有 adapter 為純文字，R1 圖片附件可預覽／保存，送出時明確告知不支援並保留草稿。圖片輸出呈現能力與模型能否看圖是不同接點，不用前者宣稱後者已實作。

PCS 文件入口由 workspace 限定已加入的根目錄，按副檔名及實際 schema 核對 Markdown、Manager、Canvas、Chat，取已保存的文字快照；不執行工作流、不跟隨附件／網路資源。單則助手回覆的「⋯ → 另存 Markdown…」沿既有排他建立、重名編號及讀回路徑建立新文件，只匯出正文；整段對話匯出仍保留原文及附件。這是使用者直接操作，尚未授權模型自行改檔。

## 決定：模組化桌面應用，加受控的推理程序

PCS 保留一個桌面應用與明確的內部模組；native 推理由 PCS 自己啟動、監督及關閉的背景程序負責。第一個引擎採 llama.cpp 的 llama-server。這個背景程序是產品隨附元件，不是要求使用者管理外部軟體。

```mermaid
flowchart TB
    UI[PCS 聊天與模型介面] --> APP[對話與模型操作]
    API[可選的本機 API] --> APP
    APP --> DOC[對話文件與恢復]
    APP --> QUEUE[推理排程與取消]
    APP --> LIB[模型目錄與下載]
    QUEUE --> PORT[引擎介面]
    PORT --> RUN[PCS 管理的 llama.cpp 程序]
    LIB --> FILE[經驗證的模型檔案]
    FILE --> RUN
    SUP[引擎版本與程序管理] --> RUN
```

這樣 native 當機可以與編輯器隔離，卸載可由程序退出確認，引擎可以獨立更新與回退。代價是需維護本機傳輸、健康檢查與程序生命週期；這些責任集中在引擎介面與程序管理，不散落到頁面。

不把 llama-cpp-python 的原生 DLL 直接載入 Qt 主程序作為首選；其記憶體生命週期、ABI 與崩潰會更直接影響 PCS。也不先建微服務平台、通用插件市場或多層遠端服務。

## 三個關鍵契約

### 1. 引擎能力與請求

建立窄而明確的 EngineAdapter，先只實作 llama.cpp adapter。能力包含文字、多模態、embedding、工具、模板、上下文、usage 與取消方式；UI 根據引擎和模型共同確認的能力顯示功能，不從模型檔名猜測。

每次推理凍結 conversation ID、message／attempt ID、request ID、owner epoch、來源 revision、模型指紋、引擎版本、參數和實際上下文。引擎切換與設定變更只影響後續請求。引擎的私有 header／server session 不作 PCS 文件身份。

事件統一為 started、delta、usage、finished、failed、cancelled，包含 request ID 與單調序號。資料接受端還要核對原 owner／revision；重複或晚到事件不能寫入另一份文件。

第一個執行策略採一個實際生成槽；首版忙碌時拒絕新請求，後續再提供 UI 排隊與取消排隊。並行模型、批次與多槽只有通過記憶體、取消和公平性驗證後才開放，不能只把數字調大就宣稱支援。

### 2. 對話保存與恢復

對話用真正版本化的 `.pcs-chat` 文件，沿用 PCS envelope、修訂／身份與原子 writer。未完成的草稿 schema 不是已接受的最終格式，需在此契約下調整。

正文、各次回覆與使用者選用的路徑分開保存。重試／重新生成保留舊回覆；編輯舊訊息建立明確的新路徑，不能悄悄改寫後續回覆的來源。執行快照可追溯是哪個模型、參數及上下文產生這次文字。

保存文件是可攜的正式內容；接收中的恢復 journal 是同一份內容的待保存交易，不是另一個獨立聊天資料庫。journal 以文件 ID、基準修訂、operation ID、序號和內容摘要關聯，定期合併到文件；寫入成功回執後才清除對應段。外部修改不自動覆蓋，衝突兩側都保留。

畫面顯示文字不等於磁碟已保存。異常退出最多只能保證恢復到已落盤的檢查點，需量測並公布檢查點間隔。重開將未完成請求標示中斷，不自動重新生成。clone／另存取得新的可寫 owner，原請求不轉交副本。

引擎記憶體中的 KV cache 是加速資料，不作對話真相。程序重啟、模型切換與前綴變更都按 cache key 作廢，保存與重開不依賴它。

### 3. 模型與引擎安裝

模型身份用來源倉庫、固定 revision、檔案集與摘要；名稱只供顯示。GGUF metadata、使用者參數、實際執行參數分開。支援分片檔案集時須全部驗證後才可載入。

下載狀態為 queued → downloading → verifying → ready，另有 paused／cancelled／failed。續傳驗證來源版本、ETag／Range／大小；不匹配就明示重新下載。TLS 保持驗證，下載到專屬暫存，驗證完整後才發布；不覆蓋使用者原有模型。

加入既有模型預設引用其原位置，明確區分「從清單移除」與「刪除實體檔案」。權重不放在使用者文件目錄，不隨聊天複製／匯出。搜尋來源先採 Hugging Face adapter，新增其它來源不改聊天核心。

引擎版本使用經固定與驗證的 manifest，記載來源版本、平台、檔案摘要及相依 runtime。新版本在另一目錄安裝、健康驗證後切換，保留可回退版本。不能跟浮動 main 自動建置正式產品。

## 程序與資源生命週期

模型狀態明列 unloaded、loading、ready、generating、stopping、unloading、failed。按鍵可用性與錯誤回復依狀態轉換，不以多個互相矛盾的布林欄位表示。

Windows 啟動不顯示終端視窗，用自有 process handle 與 Job Object 管理子程序退出；只回收自己啟動的程序。引擎只監聽 loopback，使用每次啟動的認證和握手；port 衝突時重新配置，不任意採用既有服務。程序 stdout／stderr 必須持續、有界地讀取，避免 pipe 堵塞；診斷預設不記聊天正文或憑證。

停止先作廢本次內容接受權，再發取消並確認引擎已閒置。關閉連線不能直接當作 GPU 已停止；超時可結束自有引擎並保留部分回覆。下載、載入、生成和卸載使用各自的取消語義，UI 顯示真實狀態。

GPU／RAM 估算是建議，載入結果才是實際能力。完整目標包含權重、KV cache 與上下文資源成本顯示；模型回收沿受控程序生命週期與閒置釋放設定，不把手動載入／卸載作為聊天步驟。PCS 不暗中終止 ComfyUI 或其它 GPU 程序。OOM 保留草稿與訊息，說明可降低上下文／GPU layers 或改用較小模型；不默默修改參數並重送。

上下文預檢採用固定引擎的聊天模板與 tokenizer，保留輸出預算；不得以字數或 UTF-8 bytes 冒稱精確 token。超長時提供使用者可見的處理方式；原對話完整保留，摘要／裁切必須是明確操作。禁止引擎偷偷 context shift 改變送入內容。

## 功能目標與施工順序

這是一個階段內分批完成的範圍，不把第一個能回一句話的版本稱為 LM Studio 功能完成。

| 批次 | 可用成果 | 必要驗收 |
| --- | --- | --- |
| A：執行底座與文件 | PCS 載入既有模型、多輪串流、停止、卸載、保存重開 | 真模型；載入失敗／程序崩潰；取消與晚到事件；同名文件隔離；重開不重送 |
| B：模型管理 | 應用內搜尋、下載、續傳、驗證、加入本機模型、管理磁碟位置 | 斷網、Range 不符、磁碟不足、hash 不符、取消後重開；完整模型才可載入 |
| C：完整聊天操作 | system prompt、參數預設、編輯／重新生成、回覆版本、Markdown／程式碼、匯出、速度與用量 | IME、長文、上下文上限、不同主題／字級／窄窗、草稿／歷史不丟 |
| D：本機 API 與引擎維護 | 明確開關的相容 API、請求排程、引擎更新與回退、診斷 | 認證、限額、API 與 UI 共用模型資源；升級失敗保留舊版本 |
| E：進階模型能力 | 文件問答、embedding／檢索、圖片及工具能力按模型支援接入 | 來源引用可追溯；檢索索引可重建；工具權限與取消邊界；未知能力不假啟用 |

GPT／Obsidian 聯動不在上述批次內。API 與文件介面應可供將來使用，但本階段不替這些整合新增介面或安裝插件。

## 與現有 PCS 的接點

- 文件：`workspace_locations`、`workspace_commands`、`workspace_panes`、`local_documents/io`、`identity`、recovery／index／file operations。新增完整 chat 分支，避免借 Canvas host／state。
- 服務：`service_adapters` 沿用不可變封套；專用推理工作不占檔案 `Jobs`。
- UI：`theme.visual_tokens`、既有 settings／StudioDialog、Markdown 與程式碼顯示能力；文件分頁維持單一入口。
- 退出：接 `WorkspaceShell.closeEvent`，先保存草稿／部分回覆，再停止接收與派送，等自己的工作退出後銷毀接收者。
- 既有影像模型管理只有檔案層能力，不把接受 `.gguf` 副檔名當成 LLM 模型管理已完成。

## 架構完成的證據

1. UI thread 不做模型載入、推理、網路下載或大型 hash；真長回覆期間文件操作仍可用。
2. 用可控制的假引擎驗證事件亂序、重複、取消、超時、崩潰和關閉；再以真引擎與固定模型驗證相同契約。
3. 強制中斷自有測試程序後，文件與已落盤 journal 可恢復；外部改檔、clone／另存及重開不串資料。
4. 固定模型、引擎、硬體與上下文，分開記冷啟動、首字延遲、輸出速度、峰值 RAM／VRAM、停止至閒置及卸載至資源釋放。
5. 更新／回退、離線啟動、缺失依賴、不同 DPI／IME 與正式打包均有對應證據；mock／離屏不能替代上述真實驗證。

當前已完成首版介面、文件與自有引擎接點。基礎版的 42 項契約、7 項離屏實頁及固定 R1／b11900 真多輪證據保留其原始來源；自動準備模型與介面調整另有新回執，見任務 STATUS 與 UI-REFINEMENT-VALIDATION.json。這些結果是受影響接點的有界核對；尚未完成上述全部架構目標、完整 LM Studio 功能、原生互動與效能矩陣或正式發布驗收。舊靜態回執保留，不將單模型結果擴大成全面支援。
