# 本地 Skill 與 Agent

適用 0.8.10 Pre-alpha2 的開發增量。這份實作讓既有聊天使用指定專案、規則和 Skill，並透過本地模型讀檔、搜尋及回答。它仍在驗證階段：指定技能與短範圍的自動選用已有真模型成功案例；較長的程式流程查找雖會預留回答空間，仍可能誤解分支或引用錯誤行號，不能視為可靠完成一般開發任務。

## 使用方式

1. 在「探索 → 工作資源」將模式切到 **Skill**，加入含 `SKILL.md` 的完整資料夾。清單可搜尋名稱或用途；開啟後查看來源、正文與附檔。引用來源只讀；要修改時先建立管理副本，再從既有 Markdown 編輯器儲存。重新讀取會更新登記版本。
2. 切到 **Agent**，新增名稱、已登記的本地模型、實際工作目錄、規則／參考來源，以及這個角色可用的技能。規則直接作本輪指示；參考檔依需要讀取。PCS 組別捷徑會加入根、協作庫、主組規則和該組交接入口；子組沒有專用規則時沿用主組，不把所有連結視為繼承。
3. 回到原本的聊天，在「⋯ → 協作設定」選角色並套用。直接交代任務可由模型選技能；「⋯ → 指定 Skill」會插入 `@名稱`，也可自行輸入。重名時選單使用識別碼。回覆旁的讀取紀錄可查看實際讀過的檔案及文字。

角色綁定只影響這份聊天。選「一般對話」可回到原有聊天設定；綁定角色期間，模型由角色設定決定。Skill 清單的啟停是全庫開關；每個 Agent 的技能勾選各自保存，修改 A 的可用清單不改 B。僅限手動的技能不進入自動索引。來源不見或版本改變時會明示錯誤，重新確認後才使用新版本。

工具審查沿用聊天原有選單。每次詢問時，讀取會等待本次允許或拒絕；自動審查只允許已登記且在範圍內的本地唯讀工具。停止會中止當前本地請求，保留已取得的讀取紀錄。較大的上下文會增加模型資源用量，不因某一次查找失敗而自動調高設定。

## 接點與資料歸屬

| 接點 | 責任 |
| --- | --- |
| `local_agents/sources.py` | 安全解析 YAML、完整資料夾清單與雜湊；核對明選的來源及 junction；不執行附檔。 |
| `local_agents/store.py` | 應用資料內的 Skill／專案／Agent 登記、獨立管理副本與版本核對；不接管首頁文件保存。 |
| `local_agents/page.py`、`dialogs.py` | 工作資源頁的 Skill／Agent 模式、綁定與核准視窗；閱讀／編輯重用 `MarkdownPreview`。 |
| `ChatDocument` | 凍結角色、模型、規則與技能版本，先保存本輪輸入，再交服務；只接受原 request、document ID 及 owner epoch 的事件。 |
| `LocalAIService`、`InferenceRuntime.tool_budget/tool_turn` | 與一般聊天及文字協作共用單一工作槽和自有引擎；同一引擎計算實際模板 tokens，接正式工具訊息，不把普通回答解讀成命令。 |
| `local_agents/execution.py` | 只讀工具、政策、預算、凍結來源、快取及工具迴圈；時間期限由服務在載入模型前建立，不更新 UI 或直接保存聊天。 |
| `local_agents/navigation.py` | 使用 Python AST 取得真實宣告與行段，不執行程式，也不把宣告誤稱為呼叫關係。 |
| `local_agents/transcript.py` | 送模型的去重、逐字節錄及答案階段投影；完整原始工具結果另行保存。 |
| `local_documents/chat_agent.py` | `pcs.chat-agent.v1` 的綁定及回覆證據格式；保存與重開沿既有文件 writer。 |

每次請求獨立取得角色設定；不以修改共用 `configure_model` 來切換角色。工作執行緒在開始使用前核對並讀入規則及技能附檔，來源若與已接受版本不同則拒絕；讀入後來源改動不回寫當輪內容。專案檔案按需讀取，每份記實際內容及雜湊。來源規則、原本的對話指示和一般讀取結果分開組裝。

工具活動、核准請求及回覆沿同一 owner 路徑接受。切頁不改歸屬；取消、關閉、另存後的舊事件不能寫入新 owner。證據沿原有檢查點與最終保存，不建立另一個聊天資料庫；重開不自動執行未完成任務。

含綁定或讀取證據的聊天宣告 `pcs.chat-agent.v1`，不支援的舊 reader 應明確拒絕。證據包含來源位置及實際讀取文字，會隨聊天文件保存和複製；分享聊天前應確認其中的專案內容。這些位置是惰性的歷史資料，不當作附件、可執行指令或重新讀取授權；普通附件的可攜性檢查維持不變。無 Agent 欄位的舊聊天不回填新資料。

## 工具與限制

提供 `list_skills`、`read_skill`、`read_source`、`search_files`、`read_file`。專案搜尋限設定的實際根目錄，隱藏目錄、模型相依及封存等不掃描。額外規則／參考必須明確登記；來源根本身可以是已核對的 junction，後代越界或循環不接受。沿用 `work_resources/source_io.py` 的檔案控制代碼檢查；允許 Skill 隱藏路徑只用於明選來源，原工作資源的預設限制不變。

- 完整技能每份最多 512 檔、16 MiB，單檔 2 MiB；每次最多提供 32 份技能，實際載入附檔合計 16 MiB。
- 一輪最多 24 次模型往返（包含最後回答）、40 次工具操作、512 KiB 原始讀取紀錄、480 秒（包括準備模型）；上限不會自動擴大。
- 單次專案讀取預設 80 行、最多 160 行。`read_file.symbol` 可讀指定 Python 宣告，`start` 此時是宣告內偏移；一般讀取則是絕對行號。大型 Python 檔案的第一段附宣告目錄，清楚區別目錄和實際函式正文。
- 搜尋最多掃描 12,000 個檔案、24 MiB 內容。`search_files.mode=text` 為單一字面片段，從不默默當正規表示式；`symbols` 為 Python 宣告名稱。一般至多 40 筆，單檔宣告目錄至多 80 筆；檔名支援含零層目錄的 `**`。不存在的路徑只建議實際候選；symbols 有唯一同名候選時會明示轉列其宣告，沒有唯一候選就要求縮小條件。
- 同樣的工具參數使用當輪快取；檔案分段讀取重用已取得的文字，目錄與相同版本的宣告索引不重建。模型可見的重複結果改為引用先前證據，重疊行段只提供新增行；每次完整原始工具結果仍獨立留存，快取事件指向既有內容。
- 工具呼叫限正式結構化訊息，禁止未登記的工具、Shell、專案寫入或自行新增允許根。Skill 的腳本、原宿主專有工具與 YAML 中繼欄位不因此取得執行權。

### 上下文與回答空間

每輪先使用同一引擎的聊天模板及 tokenize 結果計數，預檢與實際送出重用同一計數，只有訊息／模板選項改動才重算。回覆長度預留之外，保留 2,048～8,192 tokens 的讀取餘裕；接近上下文、輪數、讀取或時間上限時，停止工具階段，改為僅回答。

原始使用者問題和已設定規則保持完整。讀檔／搜尋投影的正文先截在 8,000 UTF-8 bytes 內，另附來源與省略標記；完整原始工具結果保存在原讀取事件。收尾投影使用原問題、規則及已取得的逐字節錄，移除歷次工具呼叫格式；工具設為不可呼叫。若仍放不下，再明示縮短工具節錄，仍放不下則報錯，不默默刪除原問題或規則。原始讀取、`projection` 及 `budget` 紀錄分開保存；沒有使用 AI 改寫來源摘要。

強制收尾一律保留 `limited`，原因顯示為讀取預算不足，不能因為產生了文字就標完成。一般輸出長度耗盡的原因維持原樣。此機制只保證有界停止與紀錄，不能判斷模型的程式理解正確。工具收尾的協定依 [llama.cpp 固定版本 server 文件](https://github.com/ggml-org/llama.cpp/blob/74b104c9ba5717116b7e65e0cd35397778653304/tools/server/README.md)，仍以實際模型模板能力及回執為準。

新增相依為固定 `PyYAML==6.0.3`。解析拒絕重複鍵、別名及不支援的型別；完整原文與未知中繼欄位保留。對 Codex 的 `agents/openai.yaml`，`allow_implicit_invocation: false` 映射為僅限明確指定；這不代表完整重現其他宿主的全部技能功能。

## 驗證範圍

`test_local_agents.py` 覆蓋完整複本、版本／範圍、角色技能清單、手動政策、路徑及上限；`test_local_agent_budget.py` 覆蓋宣告定位、逐字投影、去重、原始證據、預算與時間收尾；`test_local_agent_runtime.py` 覆蓋結構化回應、實際計數重用與模型能力拒絕；`test_local_agent_owners.py` 使用真文件 writer 及替身引擎驗證保存、取消、另存、晚到事件、部分回覆原因和單槽。介面與真模型回執另外記錄，不將替身成功當成真模型品質證據。

Windows 的 Qwen3.5-9B HauhauCS Q6_K 與 llama.cpp b11900 已完成指定真 Skill 正文／附檔，以及自動選技能後讀開發文件的案例；本次短任務複驗正常完成。較長的聊天保存流程查找仍未通過：同一完整問題與 32K／3,072 輸出預留下，改進後可提前留下文字與證據，但模型仍把編輯重送分支當成一般送出，漏掉完整 owner 條件，並引用錯誤行號。狀態保留未完成，不將此答覆當成可靠程式解釋。這不是其他模型、GPU、長任務或正式安裝的驗收。
