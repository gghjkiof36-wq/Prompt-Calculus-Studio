# 0.8.4：種子與流程恢復修復

所屬版本：0.8.4 Stage 候選的恢復修復；公開 Alpha 1 功能來源 `ea7df89dc714fc83c7e11ca32e5c7655619ec8a0`。

## 問題與影響

跨工作流切回會重複第一次種子；原生提交／載入逾時可能留下鎖定，排程狀態也未清楚反映是否真正提交。

## 修正內容

- 跨工作流切回時，保留同一原生工作流、相同採樣器已觀察到的執行狀態。「執行之前」不再因節點重建而重複第一次的種子；切換、讀取與只套用輸入不抽種子。新採樣器仍遵守 ComfyUI 首次執行規則，明確重試仍使用記錄中的種子。
- PCS 的原生提交保留獨立的短期待送清單，仍呼叫 ComfyUI 原生執行方法。原生驗證或提交後介面更新逾時，不再留下 PCS 執行鎖；遲到的舊操作不能取得下一筆原生 Run 工作。
- 若第三方擴充改寫執行入口、使這次操作無法確認使用獨立清單，逾時後保留晚回覆保護並提示重新整理，不冒險解鎖。通訊輪詢或回傳逾時也會結束該次等待，不重送已派出的要求。
- 原生工作流載入逾時會解除整頁輸入鎖、保留兩邊草稿及復原紀錄，不與尚未結束的原生載入同時回滾。如果原生載入一直不返回，須重新整理 ComfyUI 網頁；待它返回後也可在原生介面重新開啟工作流。這種情況不會自動重送生成，不能宣稱原生程式已被強制中止。
- 排程清單及內容視窗依實際提交狀態顯示「提交未確認」「失敗」等，不把尚未結束的排程範圍一律標成執行中。暫停流程時，已提交工作仍繼續。
- 操作紀錄補上收到要求、切換、套用、序列化、準備、提交與收尾階段。每次最多 64 筆，只記錄固定階段、時間及操作歸屬，不把 Prompt、圖片、權杖放進診斷事件；診斷失敗不重送工作。保留最初錯誤與後續取消／停止追蹤的區別。

## 驗證結果

離線測試使用產品的準備、提交、queue/history 回覆與結果保存流程，執行端由測試替身提供。官方前端來源的原生方法另在隔離環境檢查逾時及晚回覆。這些不等於操作真實網頁、安裝擴充或使用 GPU。

已修復兩個可穩定重現的原生等待邊界；原先偶發停滯的那次操作缺少前端階段證據，尚不能斷言唯一根因。新的階段紀錄用於再次出現時定位。架構分類、AI 模塊、ComfyUI Manager 與全面介面調整保留為後續工作。

### 歷史人工驗證清單

使用同版候選與同版擴充；更新擴充後重啟 ComfyUI 並重新整理原生網頁。保留 PCS、原生網頁及服務開啟。不要同時讓新舊候選連線到同一服務。

1. 將 A 採樣器設為「執行之前／遞增」或「隨機」，執行 A→B→A，查看 A 的實際任務種子。再用「執行之後」確認原本行為仍正常。
2. 保留 A→B，預排程只接 A，連續加入兩筆，跑完後再次執行；確認 B 使用對應 A 圖片，沒有停在零活動任務。
3. 測試一次原生工作流未開啟的錯誤，開啟正確工作流後取消舊流程，再明確執行新流程；舊項目不得補送。
4. 生成期間取消一份 PCS 流程，再使用 ComfyUI 原生 Run，確認仍可執行。不要為測試清空其他來源工作。
5. 確認沒有接 Stage 時只改輸入；一般生成、節點選圖、批次圖片及預排程仍按原有方式操作。
6. 若再次卡住，保留當時的任務紀錄截圖，尤其是「最後提交階段」及「最初錯誤」，連同操作順序回報。零活動任務本身不能證明尚未結束的提交已可重送。
