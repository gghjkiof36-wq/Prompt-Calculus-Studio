## 版本與資料相容範圍

- 新啟動旗標為 `--v0.8.10-pre-alpha.3`；舊 `--v0.8.10-pre-alpha.2` 旗標仍進入相同工作區入口。版本標籤不改資料路徑、設定檔名或資料格式。
- 擴充更新順序以 release 登記順序判定，Pre-alpha3 排在 Pre-alpha2 後面。兩個版本標籤即使具有相同來源提交，從 Pre-alpha2 到 Pre-alpha3 仍應判為可更新。
- 新建置目錄與啟動檔名稱包含 Pre-alpha3；生成啟動檔仍使用其所在目錄的 `data/`。將程式解壓到另一目錄並不會自動搬移舊資料，既有 `--root`、`--data`、`PROMPT_STUDIO_DATA` 與 `PCS-WORKSPACE.json` 規則不變。
- 第一至第四批已有的格式變更及搬遷要求仍適用；保留舊啟動旗標不代表舊版程式可以讀取新版資料。參見[搬遷契約](../../../development/workspace-migration.md)。
- 對應的啟動、更新排序與打包契約測試見 [release](../../../../tests/test_release_089.py) 與 [package](../../../../tests/test_maintenance_package.py)。MCP 的 `serverInfo.version` 由 `CURRENT.folder` 推導，為 `0.8.10-pre-alpha.3`；[傳輸測試](../../../../tests/test_mcp_probe_transport.py)保留明確版本斷言。

未提交工作樹的試打包會如實記錄 `working_changes`；只收 Git 已追蹤來源，新加入的本文件須提交後才會收錄。正式包需在提交後重建、核對空的 `working_changes`、本驗證文件及來源／包清單，不能把這次試打包當成乾淨發布包。
